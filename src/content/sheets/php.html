PHP для разработчиков

PHP — язык, который проще всего начать использовать и сложнее всего использовать хорошо. Он прощает почти всё: нестрогие сравнения, отсутствие типов, глобальное состояние, смешение логики с разметкой. Именно поэтому у него репутация языка с плохим кодом — и именно поэтому разница между junior и senior здесь особенно заметна: одни пишут на PHP 5 с новым синтаксисом, другие используют строгие типы, статический анализ и понимают, что происходит в движке.

Современный PHP 8 — это типизированный язык с перечислениями, неизменяемыми свойствами, объектами-значениями, генераторами, файберами и очень хорошим статическим анализом. Понимать нужно не только синтаксис, но и модель исполнения: процесс живёт один запрос и умирает, память управляется подсчётом ссылок, массивы копируются лениво, а самое дорогое в типичном приложении — не PHP, а ожидание базы и сети.

junior / модель / исполнение

Как выполняется PHP

БазаСпрашивают всегда

Главная особенность PHP, из которой следует почти всё остальное: shared-nothing. Каждый HTTP-запрос обрабатывается процессом, который стартует с чистого листа, отрабатывает и умирает. Между запросами в памяти не остаётся ничего — ни переменных, ни соединений, ни объектов.

текстЖизнь одного запроса
Браузер → nginx → PHP-FPM (пул процессов)
                      │
                      ├─ процесс берёт запрос
                      ├─ читает .php-файл
                      │    └─ opcache: скомпилированный байткод уже в памяти,
                      │       парсинг и компиляция пропускаются
                      ├─ выполняет байткод
                      │    └─ ваши переменные, соединения с БД, объекты —
                      │       всё создаётся заново для этого запроса
                      ├─ отдаёт ответ
                      └─ ВСЁ очищается: память, соединения, состояние

Следствия, о которых спрашивают:
  • «переменная не сохранилась между запросами» — так и должно быть;
  • состояние живёт в сессии, кэше, БД — а не в PHP;
  • утечка памяти живёт ровно один запрос (пока вы не перешли
    на долгоживущие воркеры — там правила меняются);
  • opcache на проде обязателен: без него каждый запрос заново
    парсит и компилирует все подключаемые файлы.

ВажноРазница между CLI и FPM касается не только скорости. В CLI по умолчанию нет ограничения на время выполнения, а в FPM оно есть — и там же действует таймаут веб-сервера. Долгие операции в веб-запросе обрываются на середине; их место в консольных командах и очередях.
Типичный вопрос на собеседованииПочему переменная не сохраняется между запросами?
Потому что PHP работает по модели shared-nothing: процесс инициализируется на запрос и полностью очищается после ответа. Состояние между запросами хранится вне PHP — в сессии, кэше, базе. Именно поэтому производительность приложения обычно определяется базой и сетью, а не самим языком.
ПрактикаВыведите на страницу php_sapi_name(), memory_get_peak_usage() и время выполнения. Сравните значения при работе через FPM и через CLI. Затем отключите opcache и замерьте разницу во времени ответа.

Типы, сравнения и приведение

БазаСпрашивают всегда

PHP — язык с динамической типизацией и автоматическим приведением типов. Это источник большинства «магических» багов, и именно здесь стоит быть педантичным.

phpСравнения: строгое и нестрогое
<?php
// === сравнивает значение И тип, == приводит типы
0 === '0';        // false
0 == '0';         // true

// В PHP 8 сравнение числа со строкой изменилось в лучшую сторону:
// нечисловая строка больше не превращается в 0
0 == 'foo';       // false в PHP 8 (в PHP 7 было true!)
0 == '';          // false в PHP 8
'1' == '01';      // true — обе строки числовые, сравниваются как числа
'10' == '1e1';    // true — та же причина
null == false;    // true
[] == false;      // true

// Правило: в прикладном коде используйте === всегда,
// кроме случаев, когда приведение нужно осознанно.
in_array('abc', [0, 1], true);   // третий аргумент — строгий режим
array_search($v, $arr, true);
phpЛожные значения и проверки существования
<?php
// Всё это — false при приведении к bool:
false, 0, 0.0, '', '0', [], null
// А вот это — true:
'0.0', 'false', ' ', [0], -1, '00'

// Классическая ошибка: strpos вернул 0 — позицию, а не «не найдено»
if (strpos($haystack, $needle)) { }              // ПЛОХО
if (strpos($haystack, $needle) !== false) { }   // ХОРОШО
if (str_contains($haystack, $needle)) { }        // ЛУЧШЕ (PHP 8)

// Проверки существования: разные инструменты для разных задач
isset($a['k']);              // есть ключ И значение не null
array_key_exists('k', $a); // есть ключ, даже если значение null
empty($a['k']);             // нет ключа ИЛИ значение ложное — осторожно с '0'

// Удобные операторы вместо ветвлений
$name = $data['name'] ?? 'аноним';      // null coalescing
$config['limit'] ??= 20;                // присвоить, если не задано
$city = $user?->address?->city;           // nullsafe: null вместо ошибки
ВажноЧисла с плавающей точкой нельзя сравнивать на равенство и нельзя использовать для денег: 0.1 + 0.2 !== 0.3. Для денег — целые в минимальных единицах (копейки) или строковая арифметика произвольной точности; для сравнения — сопоставление с допустимой погрешностью.
АнтипаттернПолагаться на нестрогое сравнение «чтобы работало и со строкой, и с числом». Данные из HTTP-запроса всегда строки, из базы — часто тоже. Приводите тип явно на границе ((int), (float), валидация), а дальше работайте строго — тогда сравнение перестаёт быть источником сюрпризов.
Типичный вопрос на собеседованииЧем == отличается от === и что изменилось в PHP 8?
== сравнивает после приведения типов, === — значение и тип без приведения. В PHP 8 изменилось сравнение числа со строкой: если строка нечисловая, число приводится к строке, а не наоборот. Поэтому 0 == 'foo' теперь false, хотя в PHP 7 было true — это устранило целый класс уязвимостей в проверках.
ПрактикаСоберите таблицу сравнений: возьмите значения 0, '0', '', null, false, [], 'foo' и сравните каждое с каждым через == и ===. Объясните каждое расхождение — после этого нестрогие сравнения перестанут удивлять.

Массивы и строки

База

Массив в PHP — универсальная структура: список, словарь, стек, очередь. Под капотом это упорядоченная хеш-таблица, а не классический массив, — отсюда и гибкость, и стоимость операций. Подробный разбор сложности — в конспекте по структурам данных; здесь — язык и типичные ошибки.

phpМассивы: то, что используют каждый день
<?php
// Ключи: только int и string. Всё остальное приводится.
$a['42'] === $a[42];      // один и тот же элемент — числовая строка стала int

// Перебор и преобразование
foreach ($rows as $key => $row) { }
array_map(fn ($x) => $x * 2, $nums);      // ключи теряются при нескольких массивах
array_filter($rows, fn ($r) => $r->isActive);  // КЛЮЧИ СОХРАНЯЮТСЯ!
array_values(array_filter(...));            // переиндексация после фильтра
array_reduce($items, fn ($c, $i) => $c + $i->total, 0);
array_column($rows, 'name', 'id');          // индекс id => name одной строкой

// Объединение: две разные операции
array_merge([1, 2], [3, 4]);   // [1,2,3,4] — int-ключи переиндексируются
[1, 2] + [3, 4];               // [1,2] — ключи 0 и 1 уже заняты
[...$a, ...$b];                // spread, со строковыми ключами — с PHP 8.1

// Сортировки: sort теряет ключи, asort/ksort — нет
usort($items, fn ($x, $y) => $x->price <=> $y->price);
// С PHP 8.0 сортировки стабильны: равные элементы сохраняют порядок
phpСтроки: байты, а не символы
<?php
$s = 'привет';
strlen($s);           // 12 — байтов, кириллица в UTF-8 по два байта
mb_strlen($s);        // 6 — символов
mb_substr($s, 0, 3);  // 'при' — не режет символ пополам
mb_strtoupper($s);    // 'ПРИВЕТ' — strtoupper кириллицу не тронет

// Полезное из PHP 8
str_contains($h, $n);
str_starts_with($h, $n);
str_ends_with($h, $n);

// Интерполяция и heredoc
$msg = "Привет, {$user->name}! Заказ №{$order['id']}";
$sql = <<<SQL
    SELECT * FROM orders WHERE user_id = :id
    SQL;                       // с PHP 7.3 отступ закрывающего маркера снимается

// Сборка большого текста: не конкатенация в цикле, а implode
$csv = implode("\n", array_map(fn ($r) => implode(',', $r), $rows));
ВажноТри ловушки, на которых спотыкаются регулярно: array_filter сохраняет ключи (и json_encode отдаст объект вместо массива — спасает array_values); array_merge переиндексирует целочисленные ключи, а оператор + нет; in_array без третьего аргумента сравнивает нестрого.
Антипаттернforeach ($items as &$item) с последующим обычным foreach по тому же массиву. После первого цикла переменная остаётся ссылкой на последний элемент, и второй цикл затирает его. Классический баг, который ищут часами. Если использовали ссылку — сразу после цикла делайте unset($item).
Типичный вопрос на собеседованииМассив в PHP — это массив?
Нет, это упорядоченная хеш-таблица: ключи только int и string, порядок вставки сохраняется, доступ по ключу идёт через хеш. Для последовательных целых ключей движок применяет оптимизацию и хранит только вектор значений, что экономит память и ускоряет обход.
ПрактикаНапишите функцию обрезки текста до N символов с многоточием, не ломающую слова и UTF-8. Проверьте на тексте с эмодзи. Отдельно замерьте сборку строки из 100 000 фрагментов конкатенацией и через implode.

Функции, аргументы и замыкания

База
phpСигнатуры: типы, значения по умолчанию, именованные аргументы
<?php
declare(strict_types=1);

function formatPrice(
    int $amount,                    // в копейках — не float!
    string $currency = 'RUB',
    bool $withSymbol = true,
): string {
    // ...
}

// Именованные аргументы (PHP 8.0): не нужно передавать всё подряд
formatPrice(amount: 149900, withSymbol: false);

// Переменное число аргументов и распаковка
function sum(int ...$numbers): int { return array_sum($numbers); }
sum(...[1, 2, 3]);

// Тип возврата, которого не бывает: функция всегда бросает или завершает
function fail(string $message): never { throw new RuntimeException($message); }
phpЗамыкания и стрелочные функции
<?php
$tax = 0.2;

// Классическое замыкание: внешние переменные захватываются явно
$withTax = function (float $price) use ($tax): float {
    return $price * (1 + $tax);
};

// Стрелочная функция (7.4): захват по значению автоматически, только одно выражение
$withTax = fn (float $price): float => $price * (1 + $tax);

// Захват по ссылке — когда нужно менять внешнюю переменную
$total = 0;
$add = function (float $x) use (&$total): void { $total += $x; };

// Первоклассный callable (8.1): вместо строк с именами функций
$fn = strlen(...);
$fn = $service->handle(...);
$lengths = array_map(mb_strlen(...), $words);

// Замыкание без привязки к $this — меньше сюрпризов
$pure = static fn (int $x): int => $x * 2;
Важноdeclare(strict_types=1) ставится в начало каждого файла и действует только на вызовы, сделанные из этого файла. Без него PHP молча приводит "5" к int, а "abc" вызовет ошибку только в рантайме. Со строгими типами ошибка возникает сразу и в понятном месте — это первое, что стоит включить в любом проекте.
АнтипаттернФункции с логическими флагами в аргументах: process($data, true, false, true). На месте вызова невозможно понять, что происходит. Лечится именованными аргументами, перечислениями вместо флагов или разделением на несколько функций с говорящими именами.
Типичный вопрос на собеседованииЧем стрелочная функция отличается от обычного замыкания?
Стрелочная автоматически захватывает используемые внешние переменные по значению и содержит одно выражение. Обычное замыкание требует явного use, но может содержать любой код и захватывать по ссылке. Изменить внешнюю переменную из стрелочной функции нельзя — она видит только копию.
ПрактикаНапишите функцию с именованными аргументами и значениями по умолчанию, затем перепишите набор колбэков с использованием синтаксиса первоклассных callable. Включите строгие типы и посмотрите, что перестанет работать в старом коде.

ООП: классы, интерфейсы, трейты

БазаСпрашивают всегда
phpСовременный класс на PHP 8
<?php
declare(strict_types=1);

namespace App\Domain\Orders;

final class Order
{
    private array $items = [];

    // Продвижение свойств конструктора (8.0): объявление и присвоение сразу
    public function __construct(
        public readonly string $id,        // readonly (8.1): менять нельзя
        public readonly Customer $customer,
        private OrderStatus $status = OrderStatus::Draft,
    ) {}

    public function addItem(OrderItem $item): void
    {
        if ($this->status !== OrderStatus::Draft) {
            throw new OrderAlreadyPlaced($this->id);
        }

        $this->items[] = $item;
    }

    public function total(): Money
    {
        return array_reduce(
            $this->items,
            static fn (Money $carry, OrderItem $item) => $carry->add($item->subtotal()),
            Money::zero(),
        );
    }
}

<?php
// Интерфейс — только контракт (с 8.3 у констант интерфейса можно указать тип)
interface PaymentGateway
{
    public function charge(Money $amount, Card $card): PaymentResult;
}

// Абстрактный класс — контракт плюс общая реализация
abstract class BaseGateway implements PaymentGateway
{
    public function __construct(protected readonly HttpClient $http) {}

    abstract protected function endpoint(): string;

    protected function request(array $payload): array
    {
        return $this->http->post($this->endpoint(), $payload);
    }
}

// Трейт — примесь. Хорош для техники, плох для бизнес-логики.
trait HasTimestamps
{
    private ?\DateTimeImmutable $createdAt = null;

    public function touch(): void { $this->createdAt ??= new \DateTimeImmutable(); }
}

    public static function createHard(): self { return new self(); }      // всегда A
}
ВажноНачиная с PHP 8.2 создание необъявленных (динамических) свойств объявлено устаревшим: опечатка в имени свойства теперь заметна, а не создаёт молча новое поле. Это хорошо — но старый код на этом ломается. Точечное исключение делается атрибутом, но правильный путь — объявить свойства явно.
АнтипаттернНаследование ради переиспользования кода: class OrderReport extends Order, потому что «там уже есть нужные методы». Наследование означает «является», а не «использует». Если отношения «является» нет — композиция или интерфейс. Иначе через год иерархия из пяти уровней, в которой никто не понимает, откуда взялся метод.
Типичный вопрос на собеседованииИнтерфейс или абстрактный класс?
Интерфейс — когда нужен только контракт и подменяемость: классов-реализаций может быть много, и они не связаны общим кодом. Абстрактный класс — когда, кроме контракта, есть общая реализация и состояние. Реализовать интерфейсов можно несколько, унаследоваться — только от одного класса, поэтому по умолчанию берут интерфейс плюс композицию.
ПрактикаОпишите иерархию платёжных шлюзов: интерфейс, абстрактный базовый класс с общей работой по HTTP и две реализации. Затем напишите код, который работает только с интерфейсом, и подмените реализацию заглушкой в тесте.

Ошибки и исключения

БазаСпрашивают всегда

В PHP 7+ почти всё стало исключениями, но иерархия двухголовая, и её надо знать: Throwable делится на Error (проблемы самого движка и кода) и Exception (прикладные ситуации).

    $this->logger->error('order.place.failed', [
        'exception' => $e,

} finally {

    $this->lock->release();

Типичный вопрос на собеседованииЧем Error отличается от Exception?
Оба реализуют Throwable. Error — проблемы уровня языка и рантайма: неверный тип, деление на ноль, нехватка аргументов; обычно это баг, который надо чинить, а не обрабатывать. Exception — прикладные ситуации, для которых предусмотрена реакция. Ловить \Throwable имеет смысл только на верхнем уровне, чтобы залогировать и отдать корректный ответ.
ПрактикаСоздайте иерархию исключений для одного домена: базовое исключение модуля и три конкретных с данными в свойствах. Добавьте глобальный обработчик, который логирует непойманное и отдаёт корректный ответ, и проверьте, что на проде трассировка не попадает в вывод.

Строгая типизация как инструмент

Ключевая темаСпрашивают всегда

Типы в современном PHP — не украшение, а самый дешёвый способ переложить часть проверок на движок и статический анализатор. Хорошо типизированный код ломается в момент ошибки, а не через три слоя вызовов.

Перечисления и объекты-значения

Ключевая тема

Перечисление (enum, 8.1) заменяет строковые и числовые константы типом, у которого конечное множество значений. Это убирает целый класс ошибок: невозможно передать статус, которого не существует.

phpEnum с методами и интерфейсом
<?php
enum OrderStatus: string
{
    case Draft     = 'draft';
    case Paid      = 'paid';
    case Shipped   = 'shipped';
    case Cancelled = 'cancelled';

    // Поведение живёт рядом со значениями, а не в switch по всему проекту
    public function label(): string
    {
        return match($this) {
            self::Draft     => 'Черновик',
            self::Paid      => 'Оплачен',
            self::Shipped   => 'Отправлен',
            self::Cancelled => 'Отменён',
        };
    }

    // Правила переходов — тоже здесь
    public function canTransitionTo(self $next): bool
    {
        return in_array($next, match($this) {
            self::Draft   => [self::Paid, self::Cancelled],
            self::Paid    => [self::Shipped, self::Cancelled],
            default       => [],
        }, true);
    }
}

            throw new CurrencyMismatch($this->currency, $other->currency);
        }

        return new self($this->amount + $other->amount, $this->currency);
    }

    public function format(): string
    {
        return number_format($this->amount / 100, 2, ',', ' ') . ' ₽';
    }
}

// Сравните сигнатуры:
function refund(float $amount, string $currency): void {}   // что угодно
function refund(Money $amount): void {}                     // корректно по построению
ВажноПеречисления — это объекты-одиночки: каждый вариант существует в единственном экземпляре, поэтому их можно сравнивать через === и использовать в match. У них нет состояния и их нельзя создать через new. Backed-варианты (со значением) удобны для хранения в базе, чистые — когда значение наружу не выходит.
АнтипаттернСтроковые статусы, размазанные по проекту: if ($order->status === 'payed'). Опечатка не будет замечена ни IDE, ни анализатором, а перечень допустимых значений существует только в голове. Перечисление превращает это в ошибку на этапе анализа.
Типичный вопрос на собеседованииЗачем нужны объекты-значения, если есть скалярные типы?
Они переносят инварианты в тип: Money не бывает отрицательной, Email всегда валиден, сложение разных валют невозможно. Проверка выполняется один раз при создании, дальше по коду объект корректен по построению. Плюс поведение (форматирование, арифметика) живёт рядом с данными, а не размазано по хелперам.
ПрактикаЗамените в проекте строковые статусы на перечисление с методами и правилами переходов, а работу с деньгами — на неизменяемый объект-значение в копейках. Убедитесь, что match заставляет обработать новый вариант при его добавлении.

Итераторы и генераторы

Инженерия

Генератор — функция, которая отдаёт значения по одному через yield, не строя весь результат в памяти. Это стандартный способ обработать больше данных, чем помещается в memory_limit.

phpЛенивый конвейер обработки
<?php
// ПЛОХО: файл на 2 ГБ целиком в память
function readAll(string $path): array { return file($path); }

// ХОРОШО: генератор — память постоянна независимо от размера файла
function readLines(string $path): \Generator
{
    $fh = fopen($path, 'rb');

    try {
        while (($line = fgets($fh)) !== false) {
            yield rtrim($line, "\r\n");
        }
    } finally {
        fclose($fh);          // выполнится и при прерывании обхода
    }
}

// Конвейер: каждый шаг тоже ленивый
function mapLazy(iterable $it, callable $fn): \Generator
{
    foreach ($it as $key => $value) { yield $key => $fn($value); }
}

function filterLazy(iterable $it, callable $fn): \Generator
{
    foreach ($it as $key => $value) { if ($fn($value)) { yield $key => $value; } }
}

// Обработка гигабайтного CSV при постоянной памяти
$rows = mapLazy(readLines('orders.csv'), str_getcsv(...));
$paid = filterLazy($rows, fn (array $r) => $r[3] === 'paid');

foreach ($paid as $row) {
    $importer->import($row);
}

Типичный вопрос на собеседованииКак обработать файл на 5 ГБ, если memory_limit — 256 МБ?

Память, ссылки и copy-on-write

Ключевая тема

PHP управляет памятью подсчётом ссылок: у каждого значения есть счётчик, и когда он падает до нуля, память освобождается немедленно. Отдельный сборщик нужен только для циклических ссылок между объектами.

phpCopy-on-write: копия создаётся не при передаче, а при записи
<?php
$big = range(1, 1_000_000);          // ~33 МБ

function readOnly(array $a): int
{
    return count($a);                 // копии НЕТ: только чтение
}

function touchIt(array $a): array
{
    $a[0] = 0;                        // ← ЗДЕСЬ копируется весь массив: +33 МБ
    return $a;
}

// Объекты работают иначе: переменная хранит ссылку на экземпляр,
// поэтому изменение внутри функции видно снаружи — без всякого &
function mutate(Order $order): void
{
    $order->status = OrderStatus::Paid;   // изменит исходный объект
}
phpИзмерять, а не угадывать
<?php
memory_get_usage();          // сколько занято сейчас (без учёта накладных)

Типичный вопрос на собеседованииКак в PHP работает управление памятью?
Подсчётом ссылок: значение освобождается сразу, как только на него не остаётся ссылок. Массивы и строки используют copy-on-write — копия создаётся только при записи, поэтому передача большого массива в функцию бесплатна, а его изменение внутри — нет. Циклические ссылки между объектами счётчик не обнуляет, их собирает отдельный сборщик.
ПрактикаЗамерьте пиковую память на массиве из миллиона элементов при трёх сценариях: передача в функцию без изменений, с изменением одного элемента, по ссылке. Затем перепишите скрипт импорта на генераторы и сравните пик.

Типичный вопрос на собеседованииКак правильно хранить пароли?

Параллельность: процессы, файберы, асинхронность

Инженерия

PHP по умолчанию синхронный и однопоточный: каждая операция ждёт завершения предыдущей. Параллельность достигается не потоками, а несколькими процессами — и это нормально, потому что веб-нагрузка и так распределяется по пулу процессов.

ВажноУ любого внешнего вызова обязаны быть таймаут на соединение и на ответ. Без них один зависший сервис занимает процесс до общего таймаута и способен исчерпать весь пул FPM — деградация одного стороннего API превращается в недоступность вашего приложения.
Типичный вопрос на собеседованииЕсть ли в PHP многопоточность?
В обычном веб-режиме — нет: код выполняется последовательно в одном потоке, а параллелизм обеспечивается несколькими процессами (пул FPM, воркеры очередей). Файберы дают приостановку и возобновление выполнения и служат основой асинхронных библиотек, но это конкурентность в одном потоке, а не параллельное исполнение. Для настоящей параллельной работы используют процессы, очереди или специализированные рантаймы.

Типичный вопрос на собеседованииЧто делает opcache и даст ли JIT ускорение вашему приложению?
Opcache хранит скомпилированный байткод в разделяемой памяти, устраняя парсинг и компиляцию на каждом запросе, — на проде он обязателен. JIT компилирует часть опкодов в машинный код и помогает вычислительным задачам, но в типичном веб-приложении время уходит на ожидание базы и сети, поэтому выигрыш обычно в пределах погрешности. Сначала запросы к БД, потом кэш, и только потом JIT.
ПрактикаЗамерьте время ответа приложения в трёх конфигурациях: без opcache, с opcache, с opcache и предзагрузкой. Затем включите JIT и замерьте снова — на веб-нагрузке и на синтетическом вычислительном тесте. Разница объяснит, почему порядок оптимизаций именно такой.

ВажноЛокальный замер одного запроса и поведение под нагрузкой — разные вещи. Под конкуренцией всплывают блокировки в базе, исчерпание пула процессов, борьба за соединения и промахи кэша. Прежде чем оптимизировать, убедитесь, что измеряете тот режим, в котором приложение реально живёт.
АнтипаттернМикрооптимизации языка: замена foreach на for, борьба с «медленными» строковыми функциями, переписывание циклов ради миллисекунд. На фоне одного лишнего запроса к базе в 20 мс это шум. Оптимизируют то, что показал замер, а не то, что интересно оптимизировать.
Типичный вопрос на собеседованииЭндпоинт отвечает 3 секунды. Что делаете?
Сначала разбиваю время по слоям: база, внешние вызовы, шаблоны, логика. Считаю число запросов и внешних обращений. Почти всегда находится N+1, запрос без индекса или синхронный вызов стороннего сервиса. Дальше — потоковая обработка вместо материализации, кэш дорогих участков. Профиль CPU нужен, только если после этого время всё ещё внутри PHP. И замер после каждого шага.
ПрактикаВозьмите самый медленный эндпоинт и разложите его время по слоям, добавив счётчики запросов и таймеры. Оптимизируйте по порядку из блока выше и оформите отчёт «было → стало» с вкладом каждого изменения.

senior / исполнение / воркеры

Долгоживущие процессы

Архитектура

Воркер очереди и современные рантаймы вроде Swoole, RoadRunner или FrankenPHP ломают главное допущение PHP: процесс больше не умирает после запроса. Код, годами работавший в FPM, начинает вести себя иначе.

текстЧто меняется и что с этим делать
СОСТОЯНИЕ ЖИВЁТ МЕЖДУ ЗАДАЧАМИ
  • статические свойства и синглтоны не обнуляются;
  • объект с данными текущего пользователя может «утечь» в следующий запрос;
  • глобально выставленные настройки (локаль, часовой пояс, конфиг)
    остаются в силе дальше.
  → зависимости, связанные с запросом, не кэшировать в статике;
    состояние сбрасывать явно на границе задачи.

УТЕЧКИ ПАМЯТИ НАКАПЛИВАЮТСЯ
  • раньше их убирал конец запроса, теперь процесс распухает часами.
  → ограничивать число задач и время жизни процесса,
    ставить потолок памяти, следить за графиком RSS.

СОЕДИНЕНИЯ ЖИВУТ ДОЛГО
  • соединение с БД отваливается по таймауту сервера;
  • пул соединений внезапно становится вашей заботой.
  → проверка живости и переподключение, разумные таймауты.

ДЕПЛОЙ ТРЕБУЕТ ПЕРЕЗАПУСКА
  • старый код остаётся в памяти воркеров после выкатки.
  → корректный перезапуск по сигналу: дорабатываем текущую задачу
    и завершаемся, супервизор поднимает новый процесс.
phpКорректный воркер: сигналы, лимиты, изоляция задачи
<?php
declare(strict_types=1);

pcntl_async_signals(true);

$shouldStop = false;
$handler = static function () use (&$shouldStop): void { $shouldStop = true; };

// Плавная остановка: дорабатываем текущую задачу и выходим
pcntl_signal(SIGTERM, $handler);
pcntl_signal(SIGINT, $handler);

$processed = 0;
$startedAt = time();

while (!$shouldStop) {
    $job = $queue->reserve(timeout: 5);

    if ($job !== null) {
        try {
            $handler->handle($job);
            $queue->ack($job);
        } catch (\Throwable $e) {
            $logger->error('worker.job_failed', ['job' => $job->id, 'exception' => $e]);
            $queue->retry($job);
        } finally {
            // Сброс состояния между задачами: identity map, кэши, буферы
            $container->resetScoped();
            $processed++;
        }
    }

    // Плановый перезапуск: защита от утечек и от старого кода после деплоя
    if ($processed >= 1000
        || time() - $startedAt > 3600
        || memory_get_usage(true) > 256 * 1024 * 1024
    ) {
        break;   // супервизор поднимет свежий процесс
    }
}
ВажноПрежде чем переходить на долгоживущий рантайм ради производительности, убедитесь, что узкое место — именно загрузка приложения. Если 80% времени занимает база, вы получите единицы процентов выигрыша и целый класс новых багов с утечками состояния. Сначала измерьте, потом меняйте модель исполнения.
Типичный вопрос на собеседованииЧто ломается при переходе с FPM на долгоживущие воркеры?
Всё, что опиралось на «процесс умрёт после запроса»: статические свойства и синглтоны хранят состояние между задачами, утечки памяти накапливаются, соединения с БД отваливаются по таймауту, а после деплоя в памяти остаётся старый код. Решается сбросом состояния на границе задачи, лимитами на число задач, время и память, переподключением к базе и корректным перезапуском по сигналу.
ПрактикаНапишите воркер с обработкой сигналов, лимитами по числу задач, времени и памяти, и сбросом состояния между задачами. Запустите его на сутки и постройте график потребления памяти — утечка видна сразу.

Типичный вопрос на собеседованииКак подобрать pm.max_children?
По памяти: доступная память минус запас на систему, базу и кэш, делённая на средний размер процесса под вашей нагрузкой. Размер процесса измеряется, а не берётся из головы. Ставить больше бессмысленно и опасно: при исчерпании памяти сервер уходит в своп, и деградирует всё сразу. Если процессов не хватает — сначала сокращать время запроса, а не увеличивать их число.
ПрактикаИзмерьте средний размер процесса FPM под реальной нагрузкой и пересчитайте max_children. Включите лог медленных запросов и разберите топ-5 записей за сутки. Проверьте согласованность таймаутов по всей цепочке.

Контроллеры, конфигурация и шаблоны изолировать незачем — это точки входа, они и должны быть фреймворковыми.
ПрактикаВыделите один сценарий предметной области в классы без единого упоминания фреймворка: сущности, объекты-значения, интерфейс репозитория. Напишите на него тесты без базы и убедитесь, что они выполняются за миллисекунды.

Легаси и обновление версий PHP

Архитектура

Типичная реальность: проекту восемь лет, версия PHP давно без поддержки, тестов почти нет, а бизнес хочет новых функций. Переписать с нуля почти всегда неправильный ответ — переписывание занимает годы и обычно проваливается.

текстПорядок работ, который действительно работает
1. ЗАФИКСИРОВАТЬ ПОВЕДЕНИЕ
   Тесты на ключевые сценарии — даже грубые, сквозные.
   Без них любое изменение вслепую. Это единственная страховка.

2. ПОДНЯТЬ ВЕРСИЮ PHP ДО ПОДДЕРЖИВАЕМОЙ
   Отдельным шагом, до всякого рефакторинга: безопасность и скорость
   достаются почти бесплатно. Автоматический рефакторинг помогает
   с устаревшим синтаксисом.

3. ВКЛЮЧИТЬ СТАТИЧЕСКИЙ АНАЛИЗ С ФИКСАЦИЕЙ ТЕКУЩИХ ОШИБОК
   Новый код обязан быть чистым, старый разгребается по ходу.

4. ДУШИТЬ ПОСТЕПЕННО (strangler)
   Новую функциональность писать по-новому рядом, старые куски
   заменять по частям, оставляя фасад для остального кода.

5. ГРАНИЦЫ ВМЕСТО ПЕРЕПИСЫВАНИЯ
   Выделять модули с явными контрактами. Переписывание «всего»
   не начинать: оно не заканчивается.
ВажноУ каждой версии PHP ограниченный срок поддержки: сначала период исправления ошибок, затем период только для уязвимостей, после чего обновления не выходят вовсе. Работать на неподдерживаемой версии — это не «работает и ладно», а накопление известных уязвимостей без патчей. Актуальные сроки смотрите на php.net, а обновление планируйте заранее, а не когда прижмёт.
Антипаттерн«Сначала наведём порядок, потом обновим версию». На практике порядок не наводится никогда, а обновление откладывается на годы. Правильный порядок обратный: обновить версию (это ограниченная по объёму задача с понятным результатом), а рефакторинг вести постепенно под прикрытием тестов и анализатора.
Типичный вопрос на собеседованииКак подойти к обновлению PHP на большом легаси-проекте?
Сначала обеспечить хотя бы грубое покрытие ключевых сценариев тестами — иначе изменения вслепую. Затем обновлять версии последовательно, а не прыжком через несколько, каждый шаг прогоняя тестами и выкатывая отдельно. Помогают автоматический рефакторинг устаревшего синтаксиса и статический анализатор. Отдельная типичная преграда — заброшенные зависимости, которые не поддерживают новую версию: их находят заранее.
ПрактикаВозьмите легаси-модуль и напишите на него сквозные тесты, фиксирующие текущее поведение. Затем прогоните автоматический рефакторинг под целевую версию PHP и убедитесь, что тесты остались зелёными.

Типичный вопрос на собеседованииКак вы решаете, брать библиотеку или писать своё?

Junior
  1. Почему переменные не сохраняются между запросами?Из-за модели shared-nothing: процесс инициализируется на запрос и полностью очищается после ответа. Состояние живёт в сессии, кэше или базе, а не в памяти PHP.
  2. Что делает opcache и зачем он нужен?Хранит скомпилированный байткод в разделяемой памяти, поэтому следующий запрос пропускает парсинг и компиляцию файлов. На проде обязателен: без него каждый запрос заново компилирует сотни файлов.
  3. Чем CLI отличается от FPM?Разные окружения выполнения: в CLI по умолчанию нет ограничения на время выполнения и нет веб-контекста, в FPM есть лимиты времени и таймауты веб-сервера. Долгие операции — в CLI и очереди, а не в веб-запрос.
  4. Чем == отличается от ===?Первое сравнивает после приведения типов, второе — значение и тип без приведения. В прикладном коде по умолчанию используется строгое сравнение.
  5. Что изменилось в сравнении строк и чисел в PHP 8?Если строка нечисловая, теперь число приводится к строке, а не наоборот. Поэтому 0 == 'foo' стало false, хотя раньше было true. Это убрало целый класс ошибок в проверках.
  6. Какие значения приводятся к false?false, 0, 0.0, пустая строка, строка '0', пустой массив и null. Строки '0.0', 'false' и пробел — истинные, что регулярно удивляет.
  7. Чем isset отличается от empty и array_key_exists?isset — ключ есть и значение не null. array_key_exists — ключ есть, даже если значение null. empty — ключа нет или значение ложное, поэтому '0' считается пустым.
  8. Массив в PHP — это массив?Это упорядоченная хеш-таблица: ключи только целые и строковые, порядок вставки сохраняется. Для последовательных целых ключей движок хранит компактное представление без хеш-части.
  9. Чем array_merge отличается от оператора +?array_merge переиндексирует целочисленные ключи и склеивает значения, оператор + оставляет ключи первого массива и добавляет только отсутствующие. Для списков нужен первый, для слияния настроек по ключам — второй.
  10. Почему strlen('привет') возвращает 12?Строка — массив байтов, а кириллический символ в UTF-8 занимает два байта. Для работы с символами нужны mb_*-функции, иначе обрезка ломает текст.
  11. Что делает declare(strict_types=1)?Отключает неявное приведение скалярных аргументов и возвращаемых значений для вызовов из этого файла: несоответствие типа сразу вызывает TypeError. Объявление действует на файл, а не на весь проект.
  12. Чем стрелочная функция отличается от замыкания?Стрелочная автоматически захватывает внешние переменные по значению и содержит одно выражение; замыкание требует явного use, но допускает любой код и захват по ссылке.
  13. Интерфейс или абстрактный класс?Интерфейс — только контракт, реализовать можно несколько. Абстрактный класс — контракт плюс общая реализация и состояние, но наследоваться можно лишь от одного. По умолчанию берут интерфейс и композицию.
  14. Что такое трейт и когда он уместен?Механизм примешивания методов в класс. Уместен для технических повторяющихся вещей, но не для бизнес-логики: трейт копирует код в класс, скрывает источник поведения и легко приводит к конфликтам.
  15. В чём разница self и static?self — класс, где написан код, static — класс, у которого метод вызвали (позднее статическое связывание). Для фабричных методов в базовом классе нужен static, иначе потомок получит экземпляр родителя.
  16. Чем Error отличается от Exception?Оба реализуют Throwable. Error — проблемы уровня языка (неверный тип, деление на ноль), обычно это баг. Exception — прикладные ситуации, на которые предусмотрена реакция.
  17. Зачем нужен finally?Чтобы освободить ресурсы независимо от исхода: блок выполнится и при успехе, и при исключении, и при досрочном возврате. Типичное применение — закрытие файлов, снятие блокировок, завершение транзакций.
  18. Что такое PSR-4?Стандарт автозагрузки: пространство имён отображается на каталог, класс находится по имени файла. Благодаря ему не нужно вручную подключать файлы, а структура проекта становится предсказуемой.
  19. Чем composer install отличается от update?install ставит точные версии из lock-файла — воспроизводимо, поэтому применяется в CI и на проде. update пересчитывает версии в пределах ограничений и переписывает lock; это осознанное действие разработчика.
  20. Как защититься от SQL-инъекции?Подготовленными выражениями с плейсхолдерами: запрос и данные передаются раздельно, поэтому значение не может стать частью синтаксиса. Имена таблиц, колонок и направление сортировки параметрами не передаются — только через белый список.

Middle
  1. Что дают типизированные свойства?Невозможность присвоить значение неверного типа и ошибку при чтении неинициализированного свойства вместо тихого null. Ошибка возникает в точке присвоения, а не через несколько слоёв.
  2. Что такое readonly и чем он полезен?Свойство можно задать только при инициализации из области класса; дальнейшая запись вызывает ошибку. Это неизменяемость на уровне языка: объект-значение нельзя случайно испортить, а изменение оформляется созданием нового экземпляра.
  3. Зачем перечисления, если есть константы?Перечисление — тип с конечным множеством значений: нельзя передать несуществующий статус, а match заставляет обработать все варианты. Плюс поведение живёт рядом со значениями, а не в условных конструкциях по всему проекту.
  4. Чем backed-перечисление отличается от чистого?У backed есть скалярное значение для хранения и передачи наружу, к нему применимы from() и tryFrom(). Чистое перечисление значения не имеет и годится, когда наружу оно не выходит.
  5. Что такое объект-значение и зачем он?Небольшой неизменяемый объект, определяемый своим значением: деньги, email, период. Он переносит инварианты в тип — проверка выполняется один раз при создании, дальше объект корректен по построению, а поведение живёт рядом с данными.
  6. Чем опасны __get и __call?Публичный интерфейс становится невидимым для IDE и анализатора, опечатки превращаются в рантайм-ошибки, отладка усложняется. Оправданы в прокси и обёртках, но не в обычном коде.
  7. Что делает clone и когда нужен __clone?Создаёт поверхностную копию: вложенные объекты остаются общими с оригиналом. __clone нужен, чтобы скопировать и их, иначе изменение копии затронет исходный объект.
  8. Объясните инверсию зависимостей на примере.Класс зависит от интерфейса, а конкретная реализация приходит снаружи: вместо создания SMTP-отправителя внутри сервис принимает интерфейс Mailer. В проде это SMTP, в тестах — заглушка, код не меняется.
  9. Чем внедрение зависимостей отличается от DI-контейнера?Внедрение — приём: зависимости приходят через конструктор. Контейнер — инструмент, который их собирает. Контейнер без приёма превращается в service locator, когда класс сам достаёт что хочет, и зависимости снова становятся скрытыми.
  10. Что такое генератор и когда он необходим?Функция, отдающая значения по одному через yield без построения всего результата в памяти. Необходим, когда данных больше, чем помещается: обработка больших файлов, выгрузки, постраничные обходы API.
  11. Какие ограничения у генератора?Односторонний проход: пройти повторно нельзя, count() неприменим, произвольный доступ отсутствует. Если данные нужны дважды, их приходится материализовать осознанно или перезапускать источник.
  12. Что такое copy-on-write?Массивы и строки разделяют внутреннее представление, пока никто не пишет; копия создаётся при первой записи. Поэтому передача большого массива в функцию бесплатна, а изменение внутри стоит полного копирования.
  13. Как в PHP управляется память?Подсчётом ссылок: значение освобождается сразу при обнулении счётчика. Циклические ссылки между объектами счётчик не обнуляет — их собирает отдельный сборщик, который можно вызвать вручную в длинных процессах.
  14. Чем опасны ссылки (&)?Они отключают copy-on-write, делают поток данных непредсказуемым и дают классическую ошибку с foreach, когда переменная после цикла остаётся ссылкой на последний элемент. Почти всегда лучше возвращать новое значение.
  15. Скрипт падает по нехватке памяти на большом файле. Что делать?Не поднимать лимит, а убрать материализацию: читать потоком через генератор, обрабатывать пачками, не хранить всё в массиве, агрегировать на лету. Память тогда перестаёт зависеть от объёма входа.
  16. Как организовать иерархию исключений?Интерфейс-маркер на модуль, конкретные типы с данными в свойствах, оборачивание чужих исключений с сохранением причины. Ловят по типу, а данные берут из свойств, а не разбирают текст сообщения.
  17. Чем мок отличается от заглушки?Заглушка возвращает подготовленные данные, чтобы код мог работать. Мок дополнительно проверяет факт и характер вызова: был ли метод вызван, сколько раз и с какими аргументами.
  18. Зачем статический анализ, если есть тесты?Он ловит другой класс ошибок и без запуска кода: несуществующие методы, неверные типы, недостижимые ветки, потенциальные null. Тесты проверяют поведение на выбранных сценариях, анализатор — весь код разом.
  19. Как правильно хранить пароли?Через password_hash с параметрами по умолчанию: современный алгоритм, автоматическая соль, подобранная стоимость. Проверка — password_verify, при входе — проверка необходимости пересчёта хеша. Быстрые хеши вроде md5 для паролей непригодны.
  20. Есть ли в PHP многопоточность?В обычном режиме нет: код выполняется последовательно, а параллелизм обеспечивается несколькими процессами. Файберы дают приостановку и возобновление в одном потоке и служат основой асинхронных библиотек, но это не параллельное исполнение.

  1. Что происходит с кодом от файла до выполнения?Исходник разбирается в синтаксическое дерево, компилируется в опкоды и выполняется виртуальной машиной. Opcache сохраняет опкоды в разделяемой памяти, устраняя парсинг и компиляцию на последующих запросах.
  2. Даст ли JIT ускорение вашему приложению?Обычно нет: в веб-нагрузке время уходит на базу и сеть, а JIT ускоряет вычисления. Он оправдан на счётных задачах. Приоритет оптимизаций: запросы к БД, кэш, объёмы данных — и только потом JIT.
  3. Зачем нужна предзагрузка классов и чем она неудобна?Классы компилируются один раз при старте и живут в памяти всех воркеров, что заметно ускоряет старт запроса на больших кодовых базах. Неудобство: при изменении кода требуется перезапуск, поэтому она жёстко связана с процедурой деплоя.
  4. Как подобрать pm.max_children?Доступная память минус запас, делённая на измеренный средний размер процесса. Больше ставить бессмысленно: при исчерпании памяти сервер уходит в своп и деградирует целиком. Если процессов не хватает, сначала сокращают время запроса.
  5. Что делать, если под нагрузкой начинаются 502 и 504?Смотреть, заняты ли все процессы и чем именно: обычно это долгие запросы к базе или зависшие внешние вызовы без таймаутов. Лечится таймаутами, выносом долгого в очередь и сокращением времени запроса, а не механическим увеличением числа процессов.
  6. Почему после деплоя работает старый код?При выключенной проверке времени изменения файлов opcache отдаёт старый байткод, пока процессы не перезапущены. В деплой добавляется перезагрузка FPM; для воркеров — их корректный перезапуск.
  7. Как согласовать таймауты?По всей цепочке: веб-сервер, FPM, ограничение времени выполнения, таймауты HTTP-клиента и базы. Внутренние должны быть меньше внешних, чтобы ошибка была осмысленной, а не обрывом соединения. Всё, что не укладывается, переносится в фон.
  8. Что ломается при переходе на долгоживущие воркеры?Состояние между задачами: статические свойства и синглтоны, накопление утечек, отвалившиеся по таймауту соединения с БД, старый код после деплоя. Решается сбросом состояния на границе задачи, лимитами по числу задач, времени и памяти, переподключением и перезапуском по сигналу.
  9. Как корректно останавливать воркер?По сигналу завершения выставлять флаг, дорабатывать текущую задачу и выходить из цикла; супервизор поднимет новый процесс. Резкое убийство процесса теряет задачу или оставляет её в промежуточном состоянии.
  10. С чего начинать разбор медленного эндпоинта?С разбивки времени по слоям и подсчёта запросов к базе и внешних вызовов. Почти всегда причина там. Профиль CPU нужен, только если после этого время всё ещё внутри PHP. И замер после каждого изменения.
  11. Почему микрооптимизации языка обычно бесполезны?Потому что на фоне одного лишнего запроса к базе или внешнего вызова разница между конструкциями языка теряется в шуме. Оптимизируют то, что показал замер: запросы, объёмы данных, повторные вычисления.
  12. Как внедрить статический анализ в большой легаси-проект?Зафиксировать текущие ошибки как исходное состояние, запретить появление новых и постепенно повышать уровень строгости, разгребая накопленное по мере правок. Попытка сразу включить максимальный уровень заканчивается отключением инструмента.
  13. Как подойти к обновлению версии PHP на легаси?Сначала покрыть ключевые сценарии хотя бы грубыми тестами, затем обновляться последовательно по версиям, каждый шаг проверяя и выкатывая отдельно. Помогают автоматический рефакторинг устаревшего синтаксиса и анализатор. Главная преграда обычно — заброшенные зависимости.
  14. Почему нельзя оставаться на неподдерживаемой версии PHP?Потому что для неё перестают выходить исправления, включая уязвимости, а разрыв с актуальной версией растёт, делая будущее обновление дороже. Плюс новые версии дают производительность и возможности языка бесплатно.
  15. Стоит ли изолировать код от фреймворка?Частично: доменные правила и вычисления имеет смысл держать независимыми — они тестируются мгновенно и переживают обновления. Контроллеры, конфигурация и шаблоны изолировать незачем. Полная независимость — цель, которая обычно не окупается.
  16. Как решить, писать своё или взять библиотеку?По объёму задачи и цене сопровождения. Стандартизованная инфраструктура — библиотека. Функция на двадцать строк — свой код, чтобы не тянуть дерево зависимостей. Отдельно оценивается активность проекта, поддерживаемые версии PHP и глубина проникновения библиотеки в код.
  17. Как поддерживать зависимости в порядке?Аудит уязвимостей в CI, регулярные небольшие обновления вместо накопления, отслеживание заброшенных пакетов и тех, кто блокирует обновление версии PHP. Lock-файл в репозитории, на проде только установка по нему.
  18. Где в PHP-приложении обычно теряется безопасность?В местах, которые подготовленные выражения не покрывают: сортировка и имена колонок из запроса, подключение файлов по пользовательскому пути, загрузка файлов с доверием расширению, десериализация недоверенных данных, самодельная криптография и секреты в репозитории.
  19. Как обеспечить, что ошибки не теряются?Перевести предупреждения и ошибки PHP в исключения обработчиком, добавить обработчик непойманных исключений и обработчик завершения для фатальных, логировать структурированно со сквозным идентификатором и отправлять в трекер ошибок с оповещением.
  20. Спроектируйте обработку 10 млн записей за ночь на одном сервере.Ожидается разговор о компромиссах: чтение потоком и обработка пачками с постоянной памятью; параллелизм несколькими процессами с разбиением диапазона по первичному ключу; идемпотентность и возобновляемость с сохранением позиции; пакетные операции с базой вместо построчных; контроль лага реплик и нагрузки; лимиты памяти и плановый перезапуск воркеров; логирование прогресса и алерт на остановку.

  • Не выдумывайте. На вопрос про малознакомую возможность лучше сказать, что не сталкивались, и объяснить, как разобрались бы. Выдуманный ответ проверяется одним уточняющим вопросом.
  • Приносите артефакты: замеры памяти, отчёт по оптимизации, конфигурацию пула с обоснованием, план обновления легаси. Они превращают рассказ в доказательство.
