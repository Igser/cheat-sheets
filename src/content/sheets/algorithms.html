Алгоритмы для live-coding

Секция с задачей у доски или в общем редакторе — самая нелюбимая часть собеседования для большинства PHP-разработчиков. Причина понятна: в повседневной работе редко приходится писать бинарный поиск руками, а формат ставит в неудобное положение — нужно думать, говорить и писать код одновременно, под наблюдением.

Хорошая новость в том, что на собеседованиях спрашивают не олимпиадные задачи, а десяток повторяющихся паттернов: частотный словарь, два указателя, скользящее окно, бинарный поиск, обход графа, простая динамика. Их можно выучить за месяц. И оценивают чаще не идеальное решение, а процесс: уточнили ли требования, проговорили ли подход, заметили ли граничные случаи, оценили ли сложность.

Конспект построен вокруг этого: сначала протокол решения и базовые приёмы, затем паттерны, которые закрывают большинство задач, затем то, что отличает senior — выбор между вариантами вслух, работа с граничными случаями и умение не зависнуть. Все примеры на PHP. Смежная тема — структуры данных, где разобрано, что внутри у массивов, куч и графов.

Типичный вопрос на собеседованииС чего вы начнёте решать задачу?
С уточнения условия: размер входа, типы данных, допустимые крайние случаи, что возвращать при отсутствии ответа. Затем разберу пару примеров на бумаге, чтобы убедиться, что понял задачу одинаково с вами. Потом опишу наивное решение и его сложность, предложу улучшение — и только после этого начну писать код, проговаривая, что делаю.

junior / оценка

Сложность за десять минут

База

Оценка сложности нужна не ради теории: на собеседовании её спрашивают почти всегда, а в работе она отвечает на вопрос «выдержит ли это миллион записей». Подробный разбор — в конспекте по структурам данных; здесь минимум, который нужен на задаче.

textКак считать сложность по коду
Правило: считаем, сколько раз выполнится самое внутреннее действие.

  один проход по массиву                     O(n)
  вложенный цикл по тому же массиву          O(n²)
  деление задачи пополам на каждом шаге      O(log n)
  проход + деление пополам внутри            O(n log n)
  перебор всех подмножеств                   O(2ⁿ)
  перебор всех перестановок                  O(n!)

Что НЕ влияет: константы и младшие члены.
  O(3n + 100) → O(n)      O(n² + n) → O(n²)

Память считается так же: сколько дополнительного места заняли.
  массив-счётчик размера n                   O(n)
  несколько переменных                       O(1)
  рекурсия глубиной n                        O(n) — стек тоже память!

Ориентир «пройдёт ли по времени» для типичного лимита в секунду:
  n ≤ 10        O(n!) и O(2ⁿ) допустимы
  n ≤ 1 000     O(n²) нормально
  n ≤ 100 000   нужно O(n log n)
  n ≤ 10⁷       только O(n) или O(log n)

Этот ориентир полезен и на собеседовании: он подсказывает, какого
класса решение от вас ждут, ещё до того, как вы его придумали.

Типичный вопрос на собеседованииКакая сложность у вашего решения?
Нужно назвать и время, и память, а не только время. Считается по числу выполнений самого внутреннего действия; константы отбрасываются. Полезно сразу сказать, где узкое место: «время O(n log n) из-за сортировки, память O(n) на словарь; если бы вход был отсортирован, память была бы O(1)». Такой ответ показывает, что вы понимаете структуру решения, а не заучили формулу.

junior / словари

Хеш-таблицы и счётчики

База

Самый частый приём на собеседованиях: обменять память на время. Если в задаче есть слова «найти», «встречается», «дубликат», «пара», «сколько раз» — почти наверняка решение начинается с ассоциативного массива.

phpЧетыре базовых шаблона, закрывающих десятки задач
<?php
// 1. ЧАСТОТНЫЙ СЛОВАРЬ: сколько раз встречается каждый элемент
$freq = [];
foreach ($items as $item) {
    $freq[$item] = ($freq[$item] ?? 0) + 1;
}
// Готовые варианты для простых случаев:
$freq = array_count_values($items);        // только строки и целые

// 2. МНОЖЕСТВО: быстрая проверка принадлежности за O(1)
$seen = [];
foreach ($items as $item) {
    if (isset($seen[$item])) {
        return true;                    // нашли дубликат за один проход
    }
    $seen[$item] = true;
}

// 3. ИНДЕКС: значение → позиция. Основа «двух сумм» и подобных задач
function twoSum(array $nums, int $target): ?array
{
    $index = [];                              // значение => индекс

    foreach ($nums as $i => $num) {
        $need = $target - $num;

        // Ключевая идея: ищем недостающее среди УЖЕ просмотренных.
        // Один проход вместо двух вложенных циклов: O(n) вместо O(n²).
        if (isset($index[$need])) {
            return [$index[$need], $i];
        }

        $index[$num] = $i;
    }

    return null;
}

// 4. ГРУППИРОВКА: собрать элементы по ключу за один проход
$byType = [];
foreach ($rows as $row) {
    $byType[$row['type']][] = $row;
}
phpПрефиксные суммы: диапазонные запросы за O(1)
<?php
// Задача: много запросов «сумма на отрезке [l, r]».
// Наивно — O(n) на каждый запрос. С префиксами — O(n) один раз и O(1) на запрос.

$prefix = [0];                                // prefix[i] = сумма первых i элементов
foreach ($nums as $i => $num) {
    $prefix[$i + 1] = $prefix[$i] + $num;
}

// Сумма на отрезке [l, r] включительно
$sum = $prefix[$r + 1] - $prefix[$l];

// Та же идея решает популярную задачу «число подмассивов с суммой k»:
// если prefix[j] - prefix[i] == k, значит отрезок (i, j] подходит.
// Ищем среди уже встреченных префиксов нужное значение — снова словарь.
function subarraysWithSum(array $nums, int $k): int
{
    $count = 0;
    $sum = 0;
    $seen = [0 => 1];                         // пустой префикс встречался один раз

    foreach ($nums as $num) {
        $sum += $num;
        $count += $seen[$sum - $k] ?? 0;      // сколько подходящих начал
        $seen[$sum] = ($seen[$sum] ?? 0) + 1;
    }

    return $count;
}
Практический выводСвязка «словарь уже увиденного + один проход» решает удивительно много задач: две суммы, первый повтор, самый частый элемент, подмассив с заданной суммой, анаграммы, пересечение массивов. Если задача выглядит как вложенный цикл, первый вопрос к себе — можно ли заменить внутренний цикл поиском в словаре.
Типичный вопрос на собеседованииКак найти два числа с заданной суммой?
За один проход со словарём: для каждого элемента считаем недостающее слагаемое и проверяем, встречалось ли оно раньше; если да — ответ найден, если нет — запоминаем текущий элемент. Время O(n), память O(n). Если массив отсортирован, лучше два указателя с концов: то же время без дополнительной памяти. Уточнить это стоит до написания кода.

junior / указатели

Два указателя и окно

База

Приём для задач, где нужно рассмотреть пары элементов или непрерывные отрезки. Он превращает вложенный цикл в один проход, а память из O(n) в O(1).

phpДва указателя: с концов и в одном направлении
<?php
// ВАРИАНТ 1: указатели с двух концов. Требует отсортированного массива.
function twoSumSorted(array $nums, int $target): ?array
{
    $left = 0;
    $right = count($nums) - 1;

    while ($left < $right) {
        $sum = $nums[$left] + $nums[$right];

        // Сумма мала — двигаем левый (значения растут).
        // Сумма велика — двигаем правый (значения убывают).
        if ($sum === $target) { return [$left, $right]; }

        $sum < $target ? $left++ : $right--;
    }

    return null;                            // O(n) времени, O(1) памяти
}

// ВАРИАНТ 2: медленный и быстрый указатели в одном направлении.
// Классика: удалить дубликаты из отсортированного массива на месте.
function removeDuplicates(array &$nums): int
{
    if ($nums === []) { return 0; }

    $write = 1;                              // куда пишем следующий уникальный

    for ($read = 1; $read < count($nums); $read++) {
        if ($nums[$read] !== $nums[$read - 1]) {
            $nums[$write++] = $nums[$read];
        }
    }

    return $write;                           // длина уникальной части
}
phpСкользящее окно: фиксированное и переменное
<?php
// ФИКСИРОВАННОЕ ОКНО: максимальная сумма k подряд идущих элементов.
// Идея: не пересчитывать сумму заново, а сдвигать окно.
function maxSumWindow(array $nums, int $k): int
{
    $sum = array_sum(array_slice($nums, 0, $k));
    $max = $sum;

    for ($i = $k; $i < count($nums); $i++) {
        $sum += $nums[$i] - $nums[$i - $k];   // добавили справа, убрали слева
        $max = max($max, $sum);
    }

    return $max;                             // O(n), а не O(n·k)
}

// ПЕРЕМЕННОЕ ОКНО: самая длинная подстрока без повторов.
// Шаблон: правый расширяет окно, левый сжимает при нарушении условия.
function longestUnique(string $s): int
{
    $lastPos = [];                           // символ => последняя позиция
    $start = 0;
    $best = 0;

    for ($i = 0; $i < strlen($s); $i++) {
        $ch = $s[$i];

        // Символ уже в текущем окне — сдвигаем левую границу за его прошлую позицию
        if (isset($lastPos[$ch]) && $lastPos[$ch] >= $start) {
            $start = $lastPos[$ch] + 1;
        }

        $lastPos[$ch] = $i;
        $best = max($best, $i - $start + 1);
    }

    return $best;                            // O(n) времени
}

Типичный вопрос на собеседованииКак найти самую длинную подстроку без повторяющихся символов?
Скользящим окном: правая граница движется по строке, словарь хранит последнюю позицию каждого символа. Если символ уже встречался внутри текущего окна, левая граница сдвигается за его прошлую позицию. На каждом шаге обновляем максимум. Время O(n), память O(k) по размеру алфавита. Важная деталь: сравнивать позицию с текущим началом окна, иначе граница уедет назад.

junior / поиск

Бинарный поиск

База

Простой на вид алгоритм, который почти все пишут с ошибкой на границах. Стоит один раз выучить шаблон, который не ломается, и понять вторую его форму — поиск по ответу, которая встречается на собеседованиях чаще классической.

phpШаблон, который не ломается
<?php
// Классика: найти значение в отсортированном массиве
function binarySearch(array $nums, int $target): int
{
    $lo = 0;
    $hi = count($nums) - 1;

    while ($lo <= $hi) {                       // именно <= : иначе пропустим элемент
        // Так пишут ради защиты от переполнения; в PHP это скорее привычка,
        // но на собеседовании её замечают и оценивают.
        $mid = $lo + intdiv($hi - $lo, 2);

        if ($nums[$mid] === $target) { return $mid; }

        $nums[$mid] < $target ? $lo = $mid + 1 : $hi = $mid - 1;
    }

    return -1;
}

// Чаще нужна другая форма: «первый элемент, удовлетворяющий условию».
// Этот шаблон универсален и решает «нижнюю границу», «вставку», «первый ≥ x».
function lowerBound(array $nums, int $target): int
{
    $lo = 0;
    $hi = count($nums);                       // граница ЗА последним элементом

    while ($lo < $hi) {                        // здесь строгое <
        $mid = $lo + intdiv($hi - $lo, 2);

        // «Не подходит» — двигаем нижнюю границу за середину,
        // «подходит» — сжимаем верхнюю до середины, не теряя ответ.
        $nums[$mid] < $target ? $lo = $mid + 1 : $hi = $mid;
    }

    return $lo;      // позиция первого элемента ≥ target (может быть count)
}
phpПоиск по ответу: приём, который выручает чаще всего
<?php
// Признак задачи: «минимальное X, при котором возможно...» или
// «максимальное X, при котором ещё...». Массива для поиска нет —
// ищем по диапазону возможных ответов.

// Задача: n посылок нужно развезти за d дней, порядок менять нельзя.
// Какова минимальная грузоподъёмность машины?
function minCapacity(array $weights, int $days): int
{
    // Проверка: хватит ли такой грузоподъёмности? Это простая линейная функция.
    $canDo = static function (int $capacity) use ($weights, $days): bool {
        $needed = 1;
        $current = 0;

        foreach ($weights as $w) {
            if ($current + $w > $capacity) { $needed++; $current = 0; }
            $current += $w;
        }

        return $needed <= $days;
    };

    // Границы: минимум — самая тяжёлая посылка, максимум — всё за один раз
    $lo = max($weights);
    $hi = array_sum($weights);

    // Ключевое свойство: если capacity подходит, то и любая большая подходит.
    // Значит ответы монотонны — и по ним работает бинарный поиск.
    while ($lo < $hi) {
        $mid = $lo + intdiv($hi - $lo, 2);
        $canDo($mid) ? $hi = $mid : $lo = $mid + 1;
    }

    return $lo;      // O(n · log(суммы)) вместо перебора всех вариантов
}
ВажноПризнак, по которому узнаётся поиск по ответу: в условии есть «минимальное/максимальное значение, при котором» и существует простая проверка «подходит ли данное значение». Если при этом проверка монотонна — подходит X, значит подходит и любое большее (или меньшее), — задача решается бинарным поиском по диапазону ответов. Это один из самых окупаемых приёмов: он превращает безнадёжный перебор в логарифм.
Типичный вопрос на собеседованииГде применяется бинарный поиск, кроме поиска в отсортированном массиве?
Поиск по ответу. Если задача формулируется как «найти минимальное значение параметра, при котором задача решается», и есть быстрая проверка выполнимости для конкретного значения, а свойство монотонно, то бинарный поиск по диапазону ответов даёт логарифм вместо перебора. Типичные примеры: минимальная грузоподъёмность, минимальная скорость, максимальный размер порции.

middle / сортировка

Сортировка и интервалы

Ключевое

Сортировка редко бывает самой задачей, но часто — первым шагом решения. Она стоит O(n log n) и взамен даёт порядок, из которого многое становится тривиальным: соседние элементы сравнимы, пересечения интервалов идут подряд, дубликаты стоят рядом.

phpИнтервалы: слияние пересекающихся
<?php
// Задача-классика: даны отрезки, объединить пересекающиеся.
// Ключевая идея: после сортировки по началу достаточно одного прохода —
// пересекаться может только со следующим по порядку.
function mergeIntervals(array $intervals): array
{
    if ($intervals === []) { return []; }

    usort($intervals, static fn ($a, $b) => $a[0] <=> $b[0]);

    $result = [array_shift($intervals)];

    foreach ($intervals as [$start, $end]) {
        $last = &$result[count($result) - 1];

        // Начало нового не позже конца предыдущего — значит пересекаются
        if ($start <= $last[1]) {
            $last[1] = max($last[1], $end);   // расширяем текущий
        } else {
            $result[] = [$start, $end];        // начинаем новый
        }
    }

    return $result;                            // O(n log n) на сортировку
}

// Родственная задача: максимальное число одновременных событий.
// Приём другой — «события на прямой»: раскладываем начала и концы,
// сортируем и идём со счётчиком.
function maxOverlap(array $intervals): int
{
    $events = [];

    foreach ($intervals as [$start, $end]) {
        $events[] = [$start, 1];               // начало: +1
        $events[] = [$end, -1];                // конец: −1
    }

    // При равных временах сначала обрабатываем концы: иначе посчитаем лишнее
    usort($events, static fn ($a, $b) => [$a[0], $a[1]] <=> [$b[0], $b[1]]);

    $current = 0;
    $max = 0;

    foreach ($events as [, $delta]) {
        $current += $delta;
        $max = max($max, $current);
    }

    return $max;
}

Типичный вопрос на собеседованииКак объединить пересекающиеся интервалы?
Отсортировать по началу и пройти один раз, сравнивая начало текущего с концом предыдущего: если начало не позже конца — расширяем предыдущий максимумом концов, иначе начинаем новый. Время O(n log n) за счёт сортировки, память O(n) на результат. Отдельно стоит уточнить, считаются ли пересекающимися интервалы, соприкасающиеся в одной точке, — от этого зависит знак сравнения.

middle / перебор

Рекурсия и бэктрекинг

Ключевое

Бэктрекинг — организованный перебор: строим решение по шагам, а если текущая ветка не ведёт к цели, откатываемся и пробуем другую. Так решаются задачи на комбинации, перестановки, подмножества, расстановки.

phpШаблон бэктрекинга: подходит почти ко всем задачам перебора
<?php
// Общая форма:
//   1. Условие завершения — записать текущее решение
//   2. Перебрать варианты следующего шага
//   3. Выбрать вариант → уйти вглубь → ОТМЕНИТЬ выбор
// Третий пункт (откат) — то, что отличает бэктрекинг от обычной рекурсии.

function combinations(array $nums, int $k): array
{
    $result = [];
    $current = [];

    $backtrack = static function (int $start) use (&$backtrack, &$current, &$result, $nums, $k): void {
        // 1. База: набрали нужное количество
        if (count($current) === $k) {
            $result[] = $current;
            return;
        }

        // Отсечение: даже взяв всё оставшееся, не наберём k — выходим сразу.
        // Такие отсечения превращают неподъёмный перебор в рабочий.
        if (count($nums) - $start < $k - count($current)) {
            return;
        }

        for ($i = $start; $i < count($nums); $i++) {
            $current[] = $nums[$i];            // 2. выбрали
            $backtrack($i + 1);                // 3. пошли вглубь
            array_pop($current);               // 4. ОТКАТИЛИ выбор
        }
    };

    $backtrack(0);

    return $result;
}

// Тот же шаблон решает: перестановки (нужен массив «использовано»),
// подмножества (нет условия на размер), расстановку ферзей,
// разбиение строки на палиндромы, судоку.
// Меняются только условие базы, варианты шага и отсечения.

middle / динамика

Динамическое программирование

Ключевое

Тема, которая пугает больше всех остальных. На деле динамика — это рекурсия, в которой мы перестали пересчитывать одно и то же. Практичный способ решать её на собеседовании: сначала написать честный перебор, потом добавить кэш, потом при желании переписать в таблицу.

phpТри формы одного решения: перебор → мемоизация → таблица
<?php
// Задача: сколькими способами подняться по лестнице из n ступеней,
// делая шаги по 1 или 2 ступени.

// ФОРМА 1: честный перебор. O(2ⁿ) — при n=40 уже не дождётесь.
function ways(int $n): int
{
    if ($n <= 1) { return 1; }

    return ways($n - 1) + ways($n - 2);
}

// ФОРМА 2: мемоизация — тот же код плюс кэш. O(n).
// На собеседовании это часто лучший ответ: понятно и пишется быстро.
function waysMemo(int $n, array &$memo = []): int
{
    if ($n <= 1) { return 1; }
    if (isset($memo[$n])) { return $memo[$n]; }

    return $memo[$n] = waysMemo($n - 1, $memo) + waysMemo($n - 2, $memo);
}

// ФОРМА 3: снизу вверх, таблицей. O(n) времени, O(1) памяти —
// потому что нужны только два предыдущих значения.
function waysTable(int $n): int
{
    $prev = 1;
    $curr = 1;

    for ($i = 2; $i <= $n; $i++) {
        [$prev, $curr] = [$curr, $prev + $curr];
    }

    return $curr;
}

// Практика на собеседовании: назвать перебор, сказать «здесь повторяются
// подзадачи», добавить мемоизацию, и только если попросят —
// переписать в таблицу и оптимизировать память.
phpКлассика, которую стоит уметь писать: рюкзак и наибольшая возрастающая
<?php
// РЮКЗАК: максимальная стоимость при ограничении по весу.
// dp[w] — лучшая стоимость при ёмкости w.
function knapsack(array $weights, array $values, int $capacity): int
{
    $dp = array_fill(0, $capacity + 1, 0);

    foreach ($weights as $i => $w) {
        // Идём СПРАВА НАЛЕВО: иначе один предмет посчитается несколько раз
        for ($c = $capacity; $c >= $w; $c--) {
            $dp[$c] = max($dp[$c], $dp[$c - $w] + $values[$i]);
        }
    }

    return $dp[$capacity];                    // O(n · capacity)
}

// НАИБОЛЬШАЯ ВОЗРАСТАЮЩАЯ ПОДПОСЛЕДОВАТЕЛЬНОСТЬ, простая форма O(n²).
// dp[i] — длина лучшей последовательности, заканчивающейся в i.
function lis(array $nums): int
{
    if ($nums === []) { return 0; }

    $dp = array_fill(0, count($nums), 1);

    for ($i = 1; $i < count($nums); $i++) {
        for ($j = 0; $j < $i; $j++) {
            if ($nums[$j] < $nums[$i]) {
                $dp[$i] = max($dp[$i], $dp[$j] + 1);
            }
        }
    }

    return max($dp);
    // Существует решение за O(n log n) через бинарный поиск —
    // его стоит упомянуть, даже если пишете квадратичное.
}

middle / графы

Обходы графов

Ключевое

Графы на собеседованиях появляются чаще, чем кажется: сетка на плоскости, зависимости между задачами, друзья в социальной сети, связность островов — всё это графы, просто без слова «граф» в условии.

phpДва базовых обхода: в ширину и в глубину
<?php
// BFS — обход по слоям. Главное свойство: в невзвешенном графе
// он находит КРАТЧАЙШИЙ путь. Если в задаче «минимальное число шагов» — это BFS.
function shortestPath(array $graph, string $from, string $to): int
{
    $queue = new SplQueue();
    $queue->enqueue([$from, 0]);
    $visited = [$from => true];          // помечаем ПРИ ДОБАВЛЕНИИ, а не при извлечении

    while (!$queue->isEmpty()) {
        [$node, $dist] = $queue->dequeue();

        if ($node === $to) { return $dist; }

        foreach ($graph[$node] ?? [] as $next) {
            if (!isset($visited[$next])) {
                $visited[$next] = true;
                $queue->enqueue([$next, $dist + 1]);
            }
        }
    }

    return -1;                              // пути нет
}

// DFS — вглубь. Подходит для связности, компонент, поиска циклов,
// перебора путей. Часто пишется рекурсивно.
function countIslands(array $grid): int
{
    $rows = count($grid);
    $cols = count($grid[0] ?? []);
    $count = 0;

    $sink = static function (int $r, int $c) use (&$sink, &$grid, $rows, $cols): void {
        // Единая проверка границ и «уже посещено» — так меньше шансов ошибиться
        if ($r < 0 || $c < 0 || $r >= $rows || $c >= $cols || $grid[$r][$c] !== '1') {
            return;
        }

        $grid[$r][$c] = '0';                // топим клетку вместо отдельного массива посещений

        $sink($r + 1, $c); $sink($r - 1, $c);
        $sink($r, $c + 1); $sink($r, $c - 1);
    };

    for ($r = 0; $r < $rows; $r++) {
        for ($c = 0; $c < $cols; $c++) {
            if ($grid[$r][$c] === '1') { $count++; $sink($r, $c); }
        }
    }

    return $count;                          // O(строк × столбцов)
}
phpТопологическая сортировка: порядок с учётом зависимостей
<?php
// Задача из практики: в каком порядке выполнять задачи с зависимостями,
// применять миграции, собирать модули. И заодно — есть ли циклы.
function topologicalOrder(array $graph): ?array
{
    $inDegree = [];

    foreach ($graph as $node => $deps) {
        $inDegree[$node] ??= 0;

        foreach ($deps as $dep) {
            $inDegree[$dep] = ($inDegree[$dep] ?? 0) + 1;
        }
    }

    // Начинаем с тех, у кого нет входящих зависимостей
    $queue = new SplQueue();
    foreach ($inDegree as $node => $degree) {
        if ($degree === 0) { $queue->enqueue($node); }
    }

    $order = [];

    while (!$queue->isEmpty()) {
        $node = $queue->dequeue();
        $order[] = $node;

        foreach ($graph[$node] ?? [] as $next) {
            if (--$inDegree[$next] === 0) { $queue->enqueue($next); }
        }
    }

    // Обошли не все — значит есть цикл, порядка не существует
    return count($order) === count($inDegree) ? $order : null;
}

ВажноВ BFS узел помечается посещённым в момент добавления в очередь, а не в момент извлечения. Иначе один и тот же узел попадает в очередь несколько раз, и на плотном графе сложность вырождается. Это самая частая ошибка в реализации обхода — и её замечают.
Типичный вопрос на собеседованииКогда BFS, а когда DFS?
BFS обходит по слоям и потому в невзвешенном графе даёт кратчайший путь — его берут, когда в задаче «минимальное число шагов». DFS идёт вглубь и удобнее для связности, компонент, поиска циклов и перебора путей; часто короче пишется рекурсивно. По сложности они одинаковы — O(вершин + рёбер), — а различаются гарантией и требованиями к памяти: BFS хранит слой, DFS — стек глубины.

middle / приоритеты

Куча и топ-K

Ключевое

Куча нужна там, где постоянно требуется минимум или максимум из меняющегося набора. Типичная формулировка — «K наибольших», «K ближайших», «медиана потока», «слияние отсортированных источников».

phpТоп-K: куча размера K вместо полной сортировки
<?php
// Наивно: отсортировать всё и взять K первых — O(n log n).
// С кучей размера K — O(n log k), а память O(k) вместо O(n).
// Разница принципиальна, когда n — это поток, который не влезает в память.

function topK(iterable $numbers, int $k): array
{
    // Для K НАИБОЛЬШИХ держим кучу МИНИМУМОВ: на вершине самый слабый
    // из отобранных, и его легко вытеснить более сильным кандидатом.
    $heap = new SplMinHeap();

    foreach ($numbers as $number) {
        $heap->insert($number);

        if ($heap->count() > $k) {
            $heap->extract();                 // выбрасываем наименьший
        }
    }

    return iterator_to_array($heap);      // K наибольших
}

// Очередь с приоритетом: когда нужен свой порядок
$queue = new SplPriorityQueue();
$queue->insert('задача A', 5);              // больший приоритет — раньше
$queue->insert('задача B', 10);
echo $queue->extract();                    // «задача B»

// Своя куча со сложным сравнением
final class TaskHeap extends SplMinHeap
{
    protected function compare($a, $b): int
    {
        // Сначала по дедлайну, при равенстве — по приоритету
        return [$b->deadline, $b->priority] <=> [$a->deadline, $a->priority];
    }
}
phpСлияние отсортированных источников: практичная задача
<?php
// Задача, которая встречается и на собеседованиях, и в работе:
// слить k отсортированных потоков в один отсортированный, не загружая всё в память.
function mergeSorted(array $iterators): Generator
{
    $heap = new SplMinHeap();

    // В кучу кладём по одному текущему элементу от каждого источника
    foreach ($iterators as $i => $it) {
        if ($it->valid()) { $heap->insert([$it->current(), $i]); }
    }

    while (!$heap->isEmpty()) {
        [$value, $i] = $heap->extract();
        yield $value;

        // Подтягиваем следующий элемент из того же источника
        $iterators[$i]->next();

        if ($iterators[$i]->valid()) {
            $heap->insert([$iterators[$i]->current(), $i]);
        }
    }

    // Память O(k) независимо от объёма данных: в куче всегда k элементов.
    // Это ровно тот приём, которым сливают отсортированные файлы выгрузок.
}
Типичный вопрос на собеседованииКак найти K наибольших элементов в потоке из миллиона чисел?
Кучей минимумов размера K: добавляем каждый элемент, и если размер превысил K — извлекаем наименьший. В куче всегда остаются K лучших. Время O(n log k), память O(k) — принципиально важно, если поток не помещается в память. Сортировка всего массива дала бы O(n log n) и потребовала бы держать всё целиком.

middle / строки

Задачи на строки

Ключевое

Строковые задачи любят на собеседованиях за компактность условия. В PHP у них есть своя специфика: строка — это байты, а не символы, и про это регулярно забывают.

phpТиповые приёмы: анаграммы, палиндромы, окно по строке
<?php
// АНАГРАММЫ: два слова — перестановки друг друга?
// Способ 1: отсортировать оба — O(n log n), зато одна строка.
function isAnagram(string $a, string $b): bool
{
    return count_chars($a, 1) == count_chars($b, 1);   // O(n), сравнение частот
}

// Группировка анаграмм: отсортированное слово — готовый ключ группы
function groupAnagrams(array $words): array
{
    $groups = [];

    foreach ($words as $word) {
        $chars = str_split($word);
        sort($chars);
        $groups[implode($chars)][] = $word;
    }

    return array_values($groups);
}

// ПАЛИНДРОМ: два указателя с концов, пропуская лишние символы
function isPalindrome(string $s): bool
{
    $clean = preg_replace('/[^a-z0-9]/u', '', mb_strtolower($s));
    return $clean === strrev($clean);
}

// Шаблон тот же, что для массивов: правая граница расширяет,
// левая сжимает, пока условие выполняется.

<?php
// Строка в PHP — массив БАЙТОВ. Для латиницы это незаметно,

На собеседовании правильный ход — сказать, что в PHP есть готовая функция, и тут же предложить написать её самому, раз задача про алгоритм. Знание стандартной библиотеки — это плюс, а не попытка увильнуть.
Типичный вопрос на собеседованииКак проверить, что две строки — анаграммы?
Сравнить частоты символов за один проход: время O(n), память по размеру алфавита. Альтернатива — отсортировать обе строки и сравнить, это O(n log n), зато короче. В PHP есть count_chars, который считает частоты одним вызовом. Обязательно уточнить кодировку: для кириллицы посимвольная работа требует mb_*-функций, потому что обычные работают с байтами.

<?php
// Написали решение — прогоняем по шагам ДО того, как скажут «а если...»

function maxSubarraySum(array $nums): int
{
    $best = $nums[0];                     // ← пустой массив уронит эту строку
    $current = $nums[0];

    for ($i = 1; $i < count($nums); $i++) {
        $current = max($nums[$i], $current + $nums[$i]);
        $best = max($best, $current);
    }

    return $best;
}

//   [] → падение на первой строке. Нужно решить: исключение или 0?
//        Это вопрос к интервьюеру, а не додумывание.
//   [5] → best = current = 5, цикл не выполняется, вернём 5. Верно.
//   [-3, -1, -7] → все отрицательные: вернём −1, наибольший.

senior / практика

Задачи из практики

Разбор

На senior-собеседованиях всё чаще дают не олимпиадные, а прикладные задачи: обработать большой файл, слить потоки, ограничить частоту, дедуплицировать. В них важнее не хитрый алгоритм, а работа с памятью, потоками и краевыми ситуациями.

phpОбработка файла, который не помещается в память
<?php
// Задача: файл на 10 ГБ, найти топ-10 самых частых значений.
// Первое, что проверяет интервьюер, — не загрузите ли вы файл целиком.

function topValues(string $path, int $k): array
{
    $counts = [];

    // Читаем потоком: память не зависит от размера файла
    $handle = fopen($path, 'rb');

    try {
        while (($line = fgets($handle)) !== false) {
            $value = trim($line);
            $counts[$value] = ($counts[$value] ?? 0) + 1;
        }
    } finally {
        fclose($handle);
    }

    // Здесь стоит проговорить ограничение: словарь всё ещё держит
    // ВСЕ уникальные значения. Если их миллиарды — не влезет.
    // Тогда решение другое: разбить по хешу на файлы-корзины,
    // посчитать каждую отдельно и слить результаты. Это уже
    // внешняя обработка, и упоминание такого варианта — сильный ход.

    arsort($counts);

    return array_slice($counts, 0, $k, preserve_keys: true);
}

// Генератор как ленивый конвейер: фильтрация и преобразование
// без материализации промежуточных массивов
function readLines(string $path): Generator
{
    $handle = fopen($path, 'rb');

    try {
        while (($line = fgets($handle)) !== false) {
            yield rtrim($line, "\r\n");
        }
    } finally {
        fclose($handle);
    }
}

// Пачками: обработка с постоянной памятью и пакетными операциями к БД
function chunked(iterable $items, int $size): Generator
{
    $chunk = [];

    foreach ($items as $item) {
        $chunk[] = $item;

        if (count($chunk) === $size) {
            yield $chunk;
            $chunk = [];
        }
    }

    if ($chunk !== []) { yield $chunk; }   // хвост — про него забывают чаще всего
}

Типичный вопрос на собеседованииКак найти дубликаты в файле на 100 ГБ?
Читать потоком и складывать в словарь не получится: словарь держит все уникальные значения. Практичный путь — внешняя обработка: разбить строки по хешу на N файлов-корзин так, чтобы одинаковые значения гарантированно попали в одну корзину, затем обработать каждую отдельно в памяти и объединить результаты. Если допустима приблизительность, подойдёт фильтр Блума для предварительного отсева.

  2. Найти два числа с заданной суммой.Один проход со словарём: для каждого элемента ищем недостающее слагаемое среди уже увиденных. Время O(n), память O(n). Если массив отсортирован — два указателя с концов: O(n) времени и O(1) памяти. Уточнить, нужны ли исходные индексы.
  3. Есть ли в массиве дубликаты?Множество увиденных и ранний возврат при первом повторе: O(n) времени, O(n) памяти. Если память критична и массив можно менять — отсортировать и сравнить соседей: O(n log n), память O(1). Выбор зависит от того, что дороже.
  4. Найти элемент, который встречается чаще всех.Частотный словарь за один проход, затем максимум по значениям: O(n). В PHP частоты считаются одним вызовом array_count_values. Стоит уточнить, что делать при нескольких одинаково частых элементах.
  5. Найти единственное число, встречающееся один раз, остальные — дважды.Ответ, которого ждут: исключающее ИЛИ всех элементов — одинаковые взаимно уничтожаются, остаётся уникальное. O(n) времени, O(1) памяти. Словарь тоже решает, но требует O(n) памяти, и упоминание побитового решения ценится.
  6. Найти пропущенное число в диапазоне от 1 до n.Сумма арифметической прогрессии минус фактическая сумма массива: O(n) времени, O(1) памяти. Альтернатива — исключающее ИЛИ. Стоит упомянуть риск переполнения при очень больших n, хотя в PHP это редко проблема.
  7. Развернуть массив или строку на месте.Два указателя с концов, обмен значениями до встречи: O(n) времени, O(1) памяти. Для строк в PHP есть strrev, но если просят реализовать — писать с указателями и не забыть про многобайтовые символы.
  8. Проверить, является ли строка палиндромом.Два указателя с концов с пропуском незначащих символов и приведением регистра. O(n) времени, O(1) памяти. Обязательно уточнить: учитывать ли пробелы и знаки, есть ли кириллица — от этого зависит, нужны ли mb_*-функции.
  9. Максимальная сумма k подряд идущих элементов.Скользящее окно фиксированной длины: считаем первую сумму, затем сдвигаем окно, добавляя правый элемент и вычитая левый. O(n) вместо O(n·k). Уточнить, что делать, если k больше длины массива.
  10. Самая длинная подстрока без повторяющихся символов.Переменное скользящее окно: словарь последних позиций символов, левая граница сдвигается за прошлую позицию повторившегося символа. O(n) времени. Важная деталь — сравнивать позицию с текущим началом окна, иначе граница уедет назад.
  11. Найти элемент в отсортированном массиве.Бинарный поиск: O(log n). Границы lo <= hi, середина через lo + intdiv(hi - lo, 2). Проверять на массиве из двух элементов — там ломаются почти все ошибочные варианты.
  12. Найти позицию для вставки в отсортированный массив.Вариант бинарного поиска «нижняя граница»: hi начинается за последним элементом, цикл со строгим сравнением, при подходящем элементе сжимаем hi до середины. Возвращает индекс первого элемента, не меньшего искомого. O(log n).
  13. Пересечение двух массивов.Меньший массив превратить в множество, пройти по большему и собрать совпадения: O(n + m) времени, O(min) памяти. В PHP есть array_intersect, но если просят алгоритм — писать через множество и уточнить, нужны ли дубликаты в результате.
  14. Сгруппировать анаграммы.Ключом группы делаем отсортированное слово: O(n · k log k), где k — длина слова. Альтернативный ключ — вектор частот символов, это O(n · k) без сортировки. Второй вариант упомянуть стоит: он показывает понимание стоимости.
  15. Переместить все нули в конец массива, сохранив порядок остальных.Два указателя в одном направлении: медленный указывает, куда писать следующий ненулевой элемент, быстрый идёт по массиву. Затем заполнить хвост нулями. O(n) времени, O(1) памяти, порядок сохраняется.
  16. Сумма на отрезке при множестве запросов.Префиксные суммы: один проход подготовки O(n), затем каждый запрос за O(1) как разность двух префиксов. Классическая ловушка — сдвиг на единицу: удобнее хранить префиксы с нулём в начале.
  17. Какая сложность у вложенного цикла по одному массиву?O(n²). Важнее другое — умение заметить скрытый квадрат: in_array или array_search внутри цикла выглядят как один проход, но дают то же самое. Лечится построением множества заранее.
  18. Чем isset отличается от array_key_exists?isset возвращает false для существующего ключа со значением null, а array_key_exists — true. В алгоритмах это важно, когда null — значимое значение; для счётчиков и множеств isset быстрее и достаточно.
  19. Почему array_shift опасен в цикле?Он удаляет первый элемент и переиндексирует весь массив, то есть стоит O(n). В цикле это даёт O(n²) там, где ожидался линейный проход. Для очереди нужен SplQueue, у которого извлечение за O(1), — например, в BFS.
  20. Что делать, если решение не приходит?Не молчать: разобрать пример руками, написать наивное решение и назвать его сложность, проговорить, что именно не сходится. Наивное решение — правильный первый шаг, а не поражение. Просьба о подсказке лучше, чем несколько минут тишины.

Middle · 20 задач и вопросов

Middle
  1. Объединить пересекающиеся интервалы.Отсортировать по началу и пройти один раз: если начало текущего не позже конца предыдущего — расширить предыдущий максимумом концов, иначе начать новый. O(n log n). Уточнить, считаются ли пересекающимися соприкасающиеся интервалы.
  2. Максимальное число одновременных встреч в переговорной.Разложить на события: начало +1, конец −1, отсортировать и пройти со счётчиком, запоминая максимум. Важная деталь — при равном времени сначала обрабатывать концы, иначе получится завышенный результат. O(n log n).
  3. Минимальная грузоподъёмность, чтобы развезти посылки за d дней.Бинарный поиск по ответу: диапазон от самой тяжёлой посылки до суммы всех, проверка «хватит ли данной грузоподъёмности» линейна и монотонна. O(n log суммы). Ключ к решению — заметить монотонность.
  4. Как узнать задачу на бинарный поиск по ответу?По формулировке «минимальное или максимальное значение X, при котором возможно» и наличию быстрой проверки для конкретного X. Если проверка монотонна — подходит X, значит подходит и любое большее, — работает бинарный поиск по диапазону ответов.
  5. Сгенерировать все подмножества множества.Бэктрекинг: на каждом шаге берём элемент или пропускаем, после возврата откатываем выбор. Всего 2ⁿ подмножеств. Альтернатива без рекурсии — перебор чисел от 0 до 2ⁿ−1 с трактовкой битов как маски включения.
  6. Сгенерировать все перестановки.Бэктрекинг с массивом использованных элементов: на каждом уровне перебираем неиспользованные, помечаем, уходим вглубь, снимаем пометку. O(n!) — и это неизбежно. При дубликатах во входе нужна сортировка и пропуск одинаковых на одном уровне.
  7. Какая главная ошибка в бэктрекинге?Забыть откат состояния после рекурсивного вызова: общий массив тянет мусор из предыдущей ветки. Правило — любое изменение состояния перед уходом вглубь должно иметь парную отмену. Вторая по частоте ошибка — отсутствие отсечений, из-за чего перебор не дожидается конца.
  8. Сколькими способами подняться по лестнице шагами 1 и 2?Классическая динамика: число способов для n равно сумме для n−1 и n−2. Практичный путь на собеседовании — написать рекурсию, заметить повторы, добавить мемоизацию за O(n), затем при желании свернуть в две переменные и получить O(1) памяти.
  9. Задача о рюкзаке.Динамика по остаточной ёмкости: dp[c] — лучшая стоимость при ёмкости c, для каждого предмета обновляем массив справа налево. Направление обхода критично: слева направо предмет учтётся многократно. Время O(n · capacity).
  10. Наибольшая возрастающая подпоследовательность.Простая динамика за O(n²): dp[i] — длина лучшей последовательности, заканчивающейся в i. Существует решение за O(n log n) через поддержание массива минимальных концов и бинарный поиск — его стоит упомянуть даже при написании квадратичного.
  11. Как распознать задачу на динамику?Ответ выражается через ответы на меньшие подзадачи, и при переборе эти подзадачи повторяются. Формулировки-маркеры: «сколькими способами», «минимальная стоимость», «можно ли набрать». Практический путь — перебор, затем мемоизация; таблица снизу вверх уже оптимизация.
  12. Подсчитать острова в сетке.Обход в глубину или в ширину от каждой непосещённой клетки суши, помечая всю связную область. Удобно «топить» посещённые клетки прямо в сетке вместо отдельного массива. O(строк × столбцов). Проверку границ и посещённости лучше делать одним условием на входе в функцию.
  13. Кратчайший путь в невзвешенном графе.Обход в ширину: он идёт по слоям и потому первый достигнутый путь и есть кратчайший. Узел помечается посещённым в момент добавления в очередь, а не извлечения, — иначе он попадёт в очередь несколько раз. O(вершин + рёбер).
  14. Определить порядок выполнения задач с зависимостями.Топологическая сортировка: считаем входящие степени, начинаем с нулевых, при обработке уменьшаем степени соседей и добавляем достигшие нуля. Если обошли не все вершины — есть цикл, и порядка не существует. O(V + E).
  15. Обнаружить цикл в графе.Для ориентированного — обход в глубину с тремя состояниями вершины: не посещена, в обработке, завершена; ребро в вершину «в обработке» означает цикл. Или через топологическую сортировку по числу обработанных вершин. Для неориентированного проще система непересекающихся множеств.
  16. Найти K наибольших элементов.Куча минимумов размера K: добавляем элемент, при превышении размера извлекаем наименьший. Время O(n log k), память O(k). Это принципиально лучше полной сортировки, когда n велико или данные приходят потоком.
  17. Слить k отсортированных списков.Куча размера k: держим по одному текущему элементу от каждого источника, извлекаем минимум и подтягиваем следующий из того же источника. O(n log k) времени и O(k) памяти — именно так сливают большие отсортированные файлы.
  18. Проверить, что две строки — анаграммы.Сравнить частоты символов за один проход: O(n). В PHP частоты байтов даёт count_chars. Либо отсортировать обе строки — короче, но O(n log n). Обязательно уточнить кодировку: для кириллицы нужна посимвольная работа через mb_*.
  19. Почему в PHP нужно помнить про байты в строках?Строка — это массив байтов, поэтому strlen и обращение по индексу дают неверный результат для многобайтовых символов: одна кириллическая буква занимает два байта. В алгоритмических задачах нужно либо уточнить, что вход латинский, либо использовать mb_*-функции.
  20. Реализовать LRU-кэш.Словарь для доступа за O(1) плюс двусвязный список для порядка использования: при обращении элемент перемещается в начало, при переполнении удаляется с конца. В PHP порядок вставки в массиве упорядочен, поэтому упрощённый вариант делается на массиве с удалением и повторной вставкой ключа.

Senior · 20 задач и вопросов

Senior
  1. Можно ли решить лучше?Это приглашение к разговору. Правильная реакция — назвать текущее узкое место и путь его устранения: «время O(n²) из-за вложенного цикла, убирается словарём до O(n) ценой O(n) памяти». Если улучшения не видите — честно сказать, какое ограничение мешает и в какую сторону думаете.
  2. Когда оптимизация не нужна?Когда наивное решение укладывается в ограничения, а оптимальное заметно сложнее в поддержке: при n до тысячи квадратичное решение работает мгновенно. Такой выбор нужно озвучить явно с оценкой, иначе он будет выглядеть как неумение оптимизировать.
  3. Как выбрать между словарём и двумя указателями?По ограничениям и по входу. Словарь — один проход и O(n) памяти, работает на неотсортированных данных и сохраняет индексы. Два указателя требуют порядка, зато дают O(1) памяти. Если сортировать нельзя из-за нужных исходных индексов — только словарь.
  4. Найти топ-10 самых частых значений в файле на 10 ГБ.Читать потоком, а не загружать файл: память тогда не зависит от размера. Но словарь всё ещё держит все уникальные значения, и это надо назвать вслух. Если уникальных слишком много — разбить по хешу на файлы-корзины, обработать каждую отдельно и слить результаты.
  5. Найти дубликаты в наборе, не влезающем в память.Внешняя обработка: разложить записи по N файлам по хешу так, чтобы одинаковые гарантированно попали в один файл, затем обработать каждый в памяти. Если допустима приблизительность — фильтр Блума для предварительного отсева с последующей точной проверкой кандидатов.
  6. Как обработать миллион записей с постоянной памятью?Потоком через генератор, пачками для операций к базе, без промежуточных материализаций в массивы. Ключевой признак правильного решения — память не зависит от объёма входа. Отдельно стоит упомянуть возобновляемость: сохранение позиции, чтобы обработку можно было продолжить после сбоя.
  7. Реализовать ограничение частоты запросов.Token bucket: пополняем «токены» пропорционально прошедшему времени, каждый запрос списывает один. Допускает короткие всплески и ограничивает среднюю скорость. Скользящее окно точнее, но дороже по памяти. Важно, чтобы проверка и списание были атомарными, иначе при конкурентности лимит превышается.
  8. Дедуплицировать поток событий с ограниченной памятью.Хранить идентификаторы только за окно, в котором дубликаты реально возможны, с вытеснением по времени. Полное множество за всю историю не влезет. Если допустимы редкие ложные срабатывания — фильтр Блума. Точный ответ зависит от того, что дороже: пропустить дубликат или отвергнуть уникальное.
  9. Постранично обойти API, который меняется во время обхода.Курсорной пагинацией по стабильному ключу, а не смещением: при вставках и удалениях смещение даёт дубликаты и пропуски. Дополнительно — идемпотентная обработка, чтобы повтор страницы не ломал результат, и фиксация позиции для возобновления.
  10. Как проверить своё решение на собеседовании?Прогнать вслух на четырёх входах: пустой, один элемент, обычный случай, вырожденный (все одинаковые или отсортированные наоборот). Часть проверок приведёт не к правке кода, а к вопросу об условии — это нормально и это плюс. Главное — сделать это до того, как спросят.
  11. Какие граничные случаи проверяете всегда?Пустой вход, один элемент, два элемента (на них ломаются указатели и границы окна), одинаковые значения, отсутствие ответа, границы диапазона. Для строк — пустая строка и юникод. Для графов — изолированная вершина, цикл, несвязный граф.
  12. Что делать, если дали подсказку?Услышать, повторить своими словами, встроить в решение. Спорить или игнорировать — худшая реакция: подсказка означает, что интервьюер хочет вывести вас к решению, а не поймать. Умение принять чужую идею и развить её — то же качество, что нужно на код-ревью.
  13. Как вести себя, если задача знакома и решение помните?Сказать об этом прямо. Скорость и уверенность всё равно выдадут, а признание сохраняет доверие. И всё равно объяснить логику: цель секции — увидеть ход мысли, а не факт, что вы видели задачу. Часто в ответ дают другую задачу, и лучше, если это произойдёт по вашей инициативе.
  14. Как не зависнуть, если решение не приходит совсем?Разобрать конкретный пример руками — закономерность часто видна именно там. Написать заведомо неоптимальное решение как отправную точку. Проговорить, что именно не сходится. Попросить подсказку. Молчание — единственный вариант, который точно не работает.
  15. Как связать алгоритмическую секцию с реальной работой?Примерами из практики: замена вложенного цикла словарём в медленном отчёте, потоковая обработка большого файла с постоянной памятью, выбор структуры данных под задачу, курсорная пагинация вместо смещения. Это показывает, что вы понимаете, где алгоритмическое мышление нужно, а где достаточно готовой функции.
  16. Стоит ли использовать встроенные функции PHP?Да, если задача не про реализацию алгоритма: usort, array_column, levenshtein экономят время и показывают знание стандартной библиотеки. Но если просят написать бинарный поиск, писать нужно самому. Правильный ход — назвать готовую функцию и уточнить, нужна ли своя реализация.
  17. Как оценить, уложится ли решение по времени?По размеру входа: до тысячи допустимо O(n²), до ста тысяч нужно O(n log n), при десятках миллионов — только линейное или логарифмическое. Этот ориентир подсказывает класс ожидаемого решения ещё до того, как оно придумано, и его полезно назвать вслух.
  18. Что важнее на live-coding — код или разговор?Разговор. Рабочее решение с одной неточностью, которую кандидат нашёл сам, объяснив ход мысли, оценивается выше идеального кода, написанного молча. Оценивают понимание задачи, умение сравнивать варианты, внимание к границам и реакцию на подсказку — то есть то, как человек будет работать.
  19. Как готовиться к алгоритмической секции?По паттернам, а не случайными задачами: словари, два указателя, бинарный поиск, сортировка, графы, простая динамика. Писать код руками с таймером на 25–30 минут, проговаривать вслух, возвращаться к задачам через неделю и вести список собственных ошибок — он полезнее любого учебника.
  20. Нужны ли алгоритмы PHP-разработчику в работе?Редко в чистом виде и постоянно в виде мышления: заметить скрытый квадрат, выбрать структуру данных, обработать большой объём с постоянной памятью, понять, почему запрос медленный. Честный ответ такой и есть: наизусть алгоритмы не нужны, а понимание сложности и умение видеть узкое место — нужны каждый день.

Справочник · практика

15 практических заданий

Задания устроены так, чтобы тренировать не только решение, но и формат: время, проговаривание, проверка границ. Именно это отличает подготовку от бессистемного решения задач.

Junior · 5 заданий

Junior

1. Пять задач на словарь

Решите за раз: две суммы, поиск дубликата, самый частый элемент, пересечение массивов, подмассив с заданной суммой. Все — одним проходом со словарём, без вложенных циклов.

РезультатАвтоматизм в приёме «искать среди уже увиденных» — он закрывает больше задач, чем любой другой.

2. Шаблон бинарного поиска

Напишите оба варианта — классический поиск и нижнюю границу — и проверьте на массивах из нуля, одного и двух элементов, а также при отсутствии искомого значения.

РезультатШаблон, который не ломается на границах. Проверка на двух элементах отсекает почти все ошибочные варианты.

3. Скользящее окно двух видов

Решите задачу с фиксированным окном (максимальная сумма k подряд) и с переменным (самая длинная подстрока без повторов). Сравните структуру решений — она почти одинакова.

РезультатУзнавание паттерна по формулировке «подряд идущие» или «подстрока».

4. Оценка сложности чужого кода

Возьмите пять фрагментов из своего проекта и оцените их сложность. Найдите хотя бы один скрытый квадрат — in_array в цикле, array_shift в цикле или array_merge внутри итерации.

РезультатНайденное место с квадратичной сложностью в рабочем коде и его исправление.

5. Решение вслух с записью

Возьмите одну задачу и решите её, записывая себя: уточнение условия, подход, код, проверка границ, сложность. Прослушайте запись.

РезультатПонимание, как вы звучите со стороны: длинные паузы, невнятные объяснения, привычка писать код до формулировки подхода.

Middle · 6 заданий

Middle

6. Неделя на графы

Решите пять задач: подсчёт островов, кратчайший путь в сетке, топологическая сортировка, обнаружение цикла, компоненты связности. Все — на BFS и DFS, без специальных алгоритмов.

РезультатГотовые заготовки обходов, которые пишутся по памяти, и понимание, когда какой брать.

7. Динамика через мемоизацию

Решите три задачи путём «перебор → мемоизация»: лестница, размен монет, максимальная сумма без соседних элементов. Затем перепишите одну из них в таблицу и оптимизируйте память.

РезультатРабочий подход к динамике, который не требует угадывать формулу сразу.

8. Бэктрекинг по шаблону

Реализуйте подмножества, перестановки и комбинации по одному шаблону, меняя только базу и варианты шага. Добавьте отсечения и замерьте разницу во времени.

РезультатОдин шаблон вместо трёх решений и наглядный эффект отсечений.

9. Задачи на интервалы

Решите слияние интервалов, максимальное число одновременных встреч и вставку интервала в отсортированный список. Обратите внимание на обработку соприкасающихся границ.

РезультатПонимание приёма «события на прямой», который решает целый класс задач с расписаниями.

10. Куча и потоки

Реализуйте топ-K для потока чисел, слияние трёх отсортированных генераторов и очередь с приоритетом со сравнением по двум полям.

РезультатРешения с памятью O(k) вместо O(n) — то, что отличает работу с потоками от работы с массивами.

11. Тренировка с таймером

Десять задач по 30 минут: 5 минут на уточнение и подход, 15 на код, 5 на проверку границ и сложность, 5 на разбор чужого решения. Обязательно вслух.

РезультатСписок собственных ошибок — самый полезный артефакт подготовки.

Senior · 4 задания

Senior

12. Задачи из практики

Решите четыре прикладные задачи: топ-K в большом файле потоком, слияние отсортированных выгрузок, ограничение частоты запросов, LRU-кэш. Для каждой назовите, где решение упрётся при росте данных.

РезультатРешения, устойчивые к масштабу, и умение проговорить их предел.

13. Разбор пространства решений

Возьмите пять задач и для каждой опишите три решения с разной сложностью и памятью, а затем обоснуйте выбор при разных ограничениях: маленький вход, большой вход, жёсткий лимит памяти.

РезультатЗаготовки для главного senior-навыка — обсуждать варианты, а не выдавать один.

14. Тренировочные собеседования

Проведите три сессии с коллегой в роли интервьюера, поменявшись ролями. В роли интервьюера специально давайте неполное условие и подсказки — это лучший способ понять, как выглядит хороший кандидат.

РезультатОпыт с обеих сторон стола: он меняет поведение на реальном собеседовании сильнее всего.

15. Связь с рабочими задачами

Найдите в своём проекте три места, где применим алгоритмический приём: словарь вместо вложенного цикла, потоковая обработка вместо загрузки в память, курсор вместо смещения. Реализуйте и замерьте.

РезультатЗамеры до и после — готовые примеры для ответа на вопрос «где вам это пригодилось».

План подготовки на 4 недели

Расчёт на час в будний день и два-три часа в выходной — этого достаточно, если заниматься системно. Ключевое правило: не решать задачи подряд случайно, а закрывать по одному паттерну за раз.

Неделя 1 · Процесс и базовые приёмы

Фундамент

Темы

Протокол решения и уточняющие вопросы, оценка сложности и ориентиры по размеру входа, частотный словарь, множество, индекс, группировка, префиксные суммы, два указателя, скользящее окно, бинарный поиск и поиск по ответу.

  • Выучить наизусть ориентир «какой класс решения нужен при данном n».
  • Довести до автоматизма замену in_array в цикле на множество.

Уверенные словарь, два указателя, окно и бинарный поиск плюс привычка проговаривать подход и сложность.

Неделя 4 · Формат, компромиссы, практика

Разбор

Темы

Пространство решений и обмен времени на память, когда оптимизация не нужна, граничные случаи и самопроверка, прикладные задачи с большими данными, потоки и корзины по хешу, коммуникация и поведение при затруднении, стратегия подготовки.

Практика

  • Задания 11–15: тренировка с таймером, задачи из практики, разбор пространства решений, тренировочные собеседования, связь с рабочими задачами.
  • Провести три сессии с коллегой, побывав и кандидатом, и интервьюером.
  • Составить финальный список своих ошибок и перечитать его накануне собеседования.

Результат недели

Умение обсуждать варианты вслух, решения, устойчивые к масштабу, три записанных прогона собеседования и список личных ошибок.

Контрольные вопросы

  1. Как проговаривать выбор между решениями?
  2. Когда оптимизация не нужна и как это сказать?
  3. Какие граничные случаи проверяете всегда?
  4. Как найти топ-K в файле, не влезающем в память?
  5. Что делать, если решение не приходит совсем?
  6. Как вести себя, если задача знакома?
  7. Что важнее — код или разговор?
  8. Нужны ли алгоритмы PHP-разработчику в работе?

Как вести себя на live-coding

Бонус
  • Сначала вопросы, потом код. Пять уточнений про вход, выход и края занимают минуту и часто меняют решение целиком. Молчаливое додумывание условия — минус, а не экономия времени.
  • Говорите то, что думаете. Интервьюер оценивает ход мысли, а не результат телепатии. «Сейчас я строю индекс, чтобы искать за O(1)» — короткая фраза, которая меняет впечатление от всего решения.
  • Наивное решение — законный первый шаг. Назвать перебор и его сложность, а потом улучшать — сильная стратегия. Попытка выдать оптимальное сразу заканчивается молчанием, которое выглядит хуже любого квадрата.
  • Проверяйте себя первым. Прогнать пустой вход и один элемент до того, как спросят, — самый дешёвый способ выглядеть аккуратным инженером.
  • Называйте сложность сами. Время и память, без наводящего вопроса. И лучше добавить условие: «если бы вход был отсортирован, память была бы O(1)».
  • Подсказка — это помощь, а не ловушка. Услышать, повторить своими словами, встроить. Спор с подсказкой портит впечатление сильнее нерешённой задачи.
  • Связывайте с работой. Упоминание реального случая — вложенный цикл в отчёте, обработка большого файла потоком — превращает абстрактную секцию в разговор двух инженеров.
